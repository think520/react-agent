# SQLite 并发与 WAL 日志机制

## 预写日志与快照隔离

SQLite 开启 WAL 预写日志模式后，数据变更先顺序追加到独立的后缀日志文件中，而不是直接覆写主数据库页。每个读事务开始时捕获当刻最新提交点作为一致性只读快照，从而让多个读请求与单一写入事务并行推进，写操作不再阻塞正常并发读。

## 检查点与日志回收机制

随着写入事务持续积累，WAL 文件会逐渐膨胀，需要通过 checkpoint 检查点操作把已提交的日志帧回写同步回主数据库。常规被动检查点不会强行打断活跃读事务，只有当所有旧快照读者全部释放锁后，日志起点才得以截断复用。

## 在线备份与一致性校验

面对开启并发写入的 SQLite 存储目录，直接复制底层文件容易造成主库与日志页撕裂。应当调用 SQLite 原生在线备份接口在锁协调下复制一致性快照，并在恢复落盘后立刻执行完整性校验指令排查页校验异常。

# 波波蛋 Bobodan：从第一次打开，到第二天愿意回来

**2026-11-18｜针对 [main 的 f50026f](https://github.com/think520/react-agent/tree/f50026ff4d0b8dd4a15910873c83775db186dd8a)｜产品、交互、检索与发布体验评审**

波波蛋最有辨识度的时刻，是一个学生做错题后，能说出“我错在哪里、讲义哪一段能解释、下次怎样检验自己”。今天的产品已经有支撑这个时刻的资料、引用、练习记录和复习调度。我的判断是，下一版应当让这个时刻来得更早、打断后仍接得上。单纯换组件库，最难的三个问题——第一次不知道拿它做什么、离开后丢了什么、明天凭什么再来——一个也解决不了。

## 这次实际看了什么

| 证据 | 范围与限制 |
|---|---|
| 当前提交构建、真实后端 | 前端生产构建通过。本地运行核心流程测试文件，10 项全过；走真实 FastAPI、SQLite、导入与复习逻辑，模型输出是脚本替身。这能说明数据流程接通，不能说明真实模型教得好。 |
| 临时学习库 | 自写三份中文材料（镜头、快门、版式）并生成一份纯图片 PDF，用真实接口导入、检索。刻意只开本地全文检索，验证无向量配置这一使用方式。 |
| 界面交互 | 用 React 组件和应用壳在 DOM 测试环境操作了跳过引导、离开简答题、复习接口失败和引用显示。接口异常与已有用户偏好是构造的场景。 |
| 视觉与发行 | 看了仓库里五张 1440×960 界面截图，并与当前组件及文档对照。截图是仓库的示例状态，不是这次在 Windows 上的新截图。本轮没有在干净的 Windows 机器验收、没有调用真实云端模型，也没有把主观观察当作用户研究。 |

## 1. 四个能复现的问题：先修行为，再谈改版

| 优先级 | 用户动作 → 当前结果 | 建议和验收 |
|---|---|---|
| **先修：跳过引导会改偏好** | 构造一个已设昵称、学习目标、已关记忆的用户，用没有引导完成标记的浏览器进入空库，点“跳过引导”。应用实际向偏好接口提交了空目标、空昵称和开启记忆。这里验证的是前端发出的覆盖请求。 | “跳过”只记已看过，不发偏好写请求；主动完成时用已有设置填充，仅提交改过的字段。用第二个浏览器打开同一空库验证：跳过后旧目标、昵称、记忆开关都不变。 |
| **先修：暂离简答题会丢草稿** | 写入一段回答，不提交，卸载并重新打开同一练习同一题，输入框为空。项目已经会恢复该题的辅导会话，笔记也有草稿；唯独学习者自己的未提交答案丢了。 | 按“资料库＋练习＋题目”保存草稿；回到题目恢复，成功提交或明确放弃再清理。验收：写两句→去资料库核对→回来仍在；去另一资料库，不能串答案。 |
| **先修：侧栏把没查到状态说成没任务** | 让复习接口返回 503，打开右栏“学习”，界面仍说“今天没有到期内容，可以开始一轮新练习”。这是右栏行为，不是说独立复习页也有同一个问题。 | 区分正在读取、确实为零、读取失败。失败时给“没能读取今日任务 · 重试”；保留旧数据则标明更新时间。验收：503 绝不显示“没有到期”，成功返回空队列才显示。 |
| **顺手修：代码示例里的引用被改写** | 回答正文有真实引用，同时在行内代码举例写同一标签。组件把代码中的原样字符 `[Sa1b2c3]` 渲染成了字面文本 `[1](cite:Sa1b2c3)`。学习编程的人复制示例会得到不同内容。 | 解析 Markdown 后，只替换正文文本节点，跳过行内代码、代码块和已有链接。回归用例让同一标签出现在上述四处，只有正文变成可点序号。 |

## 2. 从学生的语言看检索：知道术语的人，反而最容易搜到

同一个小库、同一种检索模式、只改问法：

| 实际查询 | 实际返回 |
|---|---|
| 景深控制 | 命中《摄影基础》里讲光圈和景深的段落。 |
| 拍人像时，怎么让身后的街道看起来糊一点？ | 零结果。 |
| 相机拍出来后面模糊前面清楚叫什么 | 命中《相机操作》的标题和快门段落，没命中景深段落。 |
| 海报上怎样让人先读大标题？ | 正确命中讲标题、引文、正文层级的段落。 |
| 赣剧的唱腔分为几类？ | 零结果；这一条符合预期，资料里确实没有。 |

这是三份讲义的定性实验，不是准确率，也不能用来评价混合检索。它揭示了两种表面相同的“搜不到”：资料里真的没有；资料里有，但初学者不知道术语。后者恰恰是学习助手该帮忙的时候。

**建议做一个小而公开的学生问法题集。** 题集同时收老师会用的术语、学生自己的描述、容易串到同类资料的问题，以及库里真没答案的问题。分别跑全文检索和混合检索，按“是否找到能回答的那一段”核分；记下“搜错了却看起来很相关”的反例。项目已有召回评测器，不必换搜索框架。用户侧先试一个便宜的改动：保留原问题，让零结果页提供“换关键词搜”和“在这份讲义里找”两个入口。只有评测证实改善，再引入查询改写；不能为了命中率把无关段落塞给学生。

**扫描课件也测了。** 纯图片 PDF 被保存，后端正确报告 0 个片段、不可检索，三份 Markdown 则可检索。这是应该保留的诚实设计。薄弱点是阅读器的无片段通用提示仍写“可能仍在建立索引”。已知提取为空时，直接写“原件已保存，可阅读；这份文件没有可检索文字。可换成带文字层的版本再导入”。先把已知结果讲清，不必为首版打包 OCR。

## 3. 从首次使用、第二天回来和视觉设计看首页

| 人和时刻 | 我会把什么放到最显眼的位置 | 如何验证 |
|---|---|---|
| **第一次来的学生，没有 Key，也没自己的讲义** | 一个可直接打开的“体验一节课”：一页讲义、一题预置选择题、一次原文定位。明确是预置题，不伪装成在线 AI。导入自己的资料是旁边的第二个入口。现有四步引导可跳过；重点是跳过后也有事能做。 | 找 5 个没看过 README 的学生，不讲解；记录有几人能在 3 分钟内独立做题并打开依据，分别卡在哪一步。3 分钟是试验目标，不是现状数据。 |
| **第二天回来的学生，只有十分钟** | 首页只选一个首要动作。例：“昨天的景深题还没答完 → 继续作答”；没有中断任务才提示到期复习，再无任务则回到最近资料。聊天框继续保留。沿用现成的练习进度和复习队列，别新建一套推荐分数。 | 准备有未完成、有到期、空库、数据不可读四种状态；让用户从首页找到合适下一步。也保留“不按推荐、开新对话”的自由。 |
| **认真阅读的人** | 保留纸张色、书页气质和波波蛋形象。仓库截图里，资料页能同时出现导航、资料列表、正文和右侧资料范围；这些区域分别合理，合起来会争阅读宽度。试一个“专注阅读”状态：收起辅助栏，引用、回到题目仍然一键可达。 | 在 1366×768 和 1440×900 做“读一段→查出处→回到原题”；观察有没有丢滚动位置、用键盘是否走得通。别只对比首页截图。 |
| **准备考试的人** | 复习小结用一句能行动的话：“你把大光圈和大 f 值混了，明天换一个拍摄情境再答。”来自真实作答的部分可回看；没有足够证据时就写“仅基于本次作答”。 | 用一个答错、一个碰巧猜对、一个重复提交的例子核对；不能把一次正确说成“已学会”。 |

**一个值得小试的差异点：把“教回给我”做进错题。** 先用自己的话解释，允许看一个提示，再换情境作答。第一轮先只对一个主题做，不做全站模式。看第二天不看提示能否答对，而不是这次生成了多少字。对数字媒体艺术学生，试题可以是“两张人像中，怎样复现左边的浅景深”；用人工准备的示例即可验证教学价值，不需要先接多模态模型。

## 4. 从信任、质量与发布看：哪些必须做，哪些别急

- **引用正确有两层。** 现有门禁能验证引用标记是否属于本轮来源，不能保证原文支持这句话。路线图自己就记录了“原文写非负权，回答却说支持负权”的反例。先抽样做三类题：原文支持、原文反驳、资料未提。让人标注关键结论，报告三类各错几次。界面沿用可点原文；即使将来有自动判断，也只标“需要核对”，不要承诺已经验证事实。
- **隐私提示应发生在做决定的地方。** 项目已在 README 说明数据留在哪里、什么配置可能联网。建议在首次选择云端模型、云端向量服务时，分别用一句话说明哪类资料会发给哪个服务。“同不同意联网查网页”和“是否用云模型处理讲义”是两个不同选择，不要让读者把“本地优先”理解成“所有计算都在本机”。
- **把整库恢复放在 Windows 预发布之前。** 题库已有导出/恢复，不能因此假定整座学习库可迁移。选一个小库，放入资料、带锚点的引用、已作答练习和笔记，恢复到另一个路径；实际从错题点回原文，比只对文件数量更有说服力。备份里包含哪些全局数据和浏览器临时草稿，应明示；默认不要把云端密钥当学习成果导出。
- **CI 补一条跨层冒烟即可。** 当前已有 mock 浏览器测试和只替换模型的真实后端闭环，两者各有价值。先补一条浏览器连真实后端的“导入讲义→阅读原文→刷新仍能打开”，不用真的花模型调用费。对重试后才过的测试单独计数；仅看最终绿灯会丢掉时序不稳的线索。无需把整套浏览器用例全改真实后端。
- **路线图现在需要一次小校正。** 当前 [ROADMAP §2](https://github.com/think520/react-agent/blob/f50026ff4d0b8dd4a15910873c83775db186dd8a/docs/ROADMAP.md) 仍写主批次要清 §3 的 P1，§3 表里却只剩 P3；同一文档的状态表又说审查 P1 已验证。建议直接写下一个要交付的用户结果、一个负责人能执行的验收动作，以及暂缓条件。“两次迭代后的学生能做什么”比再加一行“已审查”更有用。

## 5. 如果只有两轮迭代

1. **第一轮：不替用户做决定，不让他白写。** 先修跳过引导、简答草稿、侧栏假空态，再顺手修代码里的引用；把“另一浏览器＋已有偏好”“同一题离开再回来”“读失败后恢复”留下作回归。可以单独发一个小版本。
2. **第二轮：做一堂别人不用你解释也会用的课。** 用一份示例讲义串起离线选择题、原文定位和下次继续；首页只为这条路径改主次。请 5 位新用户试，再找其中几位次日回来。若他们能答题却找不到依据，先改定位；若能找到依据却不知道次日做什么，先改恢复入口。
3. **发布门槛单独守住。** 在扩大用户范围前做干净 Windows 安装、整库异地恢复、少量真实模型引用抽查。先不重做组件库、不扩移动端、不加多 Agent 编排，也不因这次全文检索小样本就更换向量数据库。

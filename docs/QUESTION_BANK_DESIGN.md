## 2. 参考调研（2026-09-10）

### 2.1 本地可读源码（价值最高）

**DeepTutor `deeptutor/tools/question_bank.py`** —— 与 Bobodan 最同构的题库设计：

- 题库 = `notebook_entries` 表，定位是「**该学习者已作答的题**」；与 notes **明确分开**：notes 是用户留存的散文，bank entries 是**有正确答案的判分题**。
- **一个工具、五个动作**（刻意保持短序列「先看，再归档」）：
  - `overview`：计数 + 已有分类名（无需 id，天然的第一步）；
  - `list`：按过滤列出，每条前缀 id；
  - `organize`：按**分类名**归档，不存在则创建——**刻意按名字寻址**："学习者说的是『我的错题集』，不是 category 7"，且两步 create+file 会多一个让模型掉链子的地方；
  - `unfile`：移出分类；`bookmark`：星标/取消。
- 过滤：`all / wrong / bookmarked / uncategorized`。
- 上限：list 默认 20、最大 100；一次最多 200 个 id；分类名 ≤ 100 字；题目预览 160 字、答案预览 60 字（**列表是"一次决策的工作集"，不是倾倒**）。
- **动机原文**："Before this tool existed the agent had no way to touch the bank, so \"file my wrong answers into my new question set\" landed in a notebook instead: the only writable surface it could see." → **agent 没有题库工具时，用户的"整理错题"会落进笔记**。这正是 Bobodan 当前的风险。
- 错误一律 `ok=False` + 可行动句子，从不抛异常。

**OpenMAIC**：题目被当作**可编辑内容**（`components/edit/surfaces/quiz/`、`lib/chat/quiz-results-for-store-state.ts`、还能导出到视频），说明题目可以是"资产"而不只是"记录"。

## 4. 已定决策

### D1 题库边界 → **B：收所有生成过的题，用状态区分**

收**所有生成过的题**（未作答 / 已作答 / 错题 / 已收藏），**默认视图只显示「已作答或已收藏」**。

理由：generate_questions 本就往 questions 表写每一道题，选 B 等于「把已有表接上界面」（零迁移）；若只收已作答的题，会**藏起「生成了 5 道只做了 1 道」里的另外 4 道**。DeepTutor 只收已作答，是因为它的表定位是「笔记本条目」（学习记录），而 Bobodan 的 questions 表本就是题目库——照搬会把别人的存储形态当成产品结论。出题编辑器 / QTI 导入属于另一量级，可在同一张表上后续叠加，不阻塞本轮。

### D2 组织方式 → **B：复用已有维度，不自建分类**

主轴用**已有维度**：**概念 / 资料 / 题型 / 难度 / 状态**；**收藏**承担「我的重点」；「我的错题集」这类需求用**命名练习集**（= 一份 question_ids 的命名集合，可一键重练）承载，**不新造分类体系**。

实测依据（该资料库）：**17/17 题带 concepts**（18 个概念）、**17/17 题带 sources**——概念轴与资料轴**零成本、零迁移**；而自建分类**一条数据都没有**。概念轴还能把题库接回主线（概念 → 掌握度 → 复习队列 → 知识地图）；自建分类是平行体系，不驱动任何学习状态，属于「新增第二套业务状态」。DeepTutor 引入分类的根本原因是它**没有概念图谱**。命名练习集复用了 quiz_sessions.question_ids 已有的形态，比「名字→分类→再挑题」少一步。

### D9 题目来源与联网题边界 → **A：与本地题走同一条证据链**

题库的来源有三类，**共用同一条证据链**：

1. **本地生成**（现状）：从 `questions.sources` 指向的原文 chunk 出题；
2. **联网生成**（现状）：无本地证据 → 返回 web_consent_required 征求同意 → 用户勾选候选 → 读正文 → 存快照（research.db）→ 出题，标 attribution_kind="web"；
3. **联网搜现成题**（**新增**）：把找到题目的**来源页存成不可变快照**，题同样标 attribution_kind="web"，题库与题卡**明确显示「联网来源」并可点回原文**。

**掌握度只记在已审查概念上**；联网题引出的**新概念只进候选**（复用 P5F.1 的候选机制），不直进知识地图。

理由：这套机器已经存在（`quiz_service.py:126-134`、`quiz_tools.py:55`），搜现成题只需复用，不新增边界语义；对用户重要的不是「谁写的题」而是「能不能点回原文」。另两个选项都被否：C（无标记同等对待）会摧毁「原文是事实来源」的边界；D（只做即时练习）则让搜来的题无法留存与重练。B 的「待核实」是重复授权——用户勾选来源本身就是授权。

> **约束（交给 D7）**：搜来的题属于**第三方内容**。本地个人练习无碍，但**将来 QTI / 导出 / 分享必须排除或显式标注**，否则构成再分发。

### D3 收藏语义 → **B：标记 + 一键「练收藏的题」，不碰调度**

收藏是**用户自己的标记**，可以一键把收藏的题**临时组卷**来练；**不改复习队列、不动掌握度**。练完的作答照常回写掌握度。

理由：复习队列的权威是掌握度引擎（SM-2 按**概念**调度，题只是载体；`learning/scheduler.py`）。让收藏直接插队会在「今天该练什么」上造出第二个权威，违反 `ROADMAP` 已拍板的「模型管教学、引擎管算术」。更关键的是**SM-2 的 interval_days 表达记忆强度，收藏表达「我想再看」**——混进同一队列后再也无法解释某题为何出现。命名集合的需求已由 D2 的命名练习集承载，收藏保持零摩擦。

### D5 复习与题库的联动 → **A：复习读题库的错题，调度权仍在引擎**

复习页的「错题」**直接读题库的错题筛选**（同一个真相源，**不再被 20 条截断**），并给出口「去题库看全部错题 / 一键练这些错题」；**今日复习队列仍由掌握度引擎按概念计算**，题库不夺调度权。

**错题定义（本次一并确定）**：该题**最近一次作答的 verdict 是 incorrect**。E15 之后 partial 归「学习中」，**不算错题**；重练答对后该题**自动脱离错题**。

理由：现状「错题」是 `learning_service.py:109-134` → `get_wrong_answer_book(limit=20)` 的**20 条上限派生视图**，而题库本来就要有「错题」状态——让复习读它是「一个真相源」。C/D 会让题库反向决定今日队列，与 D3 否掉 C 同源（第二个权威 + 混淆 interval 语义）；B 则必然出现"同一批错题两处显示不一致（一处 20、一处全量）"。

### D4 与对话的联动 → **A：只读 + 收藏给 agent；结构变更走 UI / 提案**

agent 拿到三类动作：

- **bank_overview**：计数（未作答 / 已作答 / 错题 / 已收藏）与概念分布（无需 id，天然第一步）；
- **bank_list**：按筛选列出（状态 / 概念 / 资料 / 题型 / 难度），**每条带短 id**，agent 用它引用；
- **bank_bookmark**：星标 / 取消（D3 已定：标注、可撤销、不驱动调度）。

**命名练习集的建 / 改走 UI 或走提案确认**，agent 不直接改题库结构。对话里可以**引用某一道题**：UI 上「问 AI」带 question_id，agent 也能按筛选取题讲解或出变式（两者指向同一个稳定 id）。

理由：该项目已立下两条纪律——AI 对资料 / 记忆的写入一律走提案或确认（CLAUDE.md）；只读工具可并行、写操作严格串行（AG-2.3）。收藏是最低风险的写（标注、可撤销、不驱动调度），适合交给 agent；而"建集 / 改组"改变的是用户的组织结构，属于长期资产，适合 UI + 提案。DeepTutor 的文档写明了反向教训："agent 没有题库工具时，用户让它『把错题整理成我的题集』会落进笔记，因为笔记是它唯一能写的表面"——给全量写权限则相反：agent 会改用户资产而用户事后才发现。

### D6 UI 位置 → **A：练习页的一个视图，不新增一级导航**

题库 = **练习页的一个视图**（/practice/bank 或练习页内标签），**侧栏不新增一级**；入口来自练习页本身、复习页（D5 的「去题库看全部错题」）与对话（D4 的引用某题）。

理由：`PROJECT_GUIDE.md` §2.3 的 IA 里 Study 一等入口是 Today / Chat / Practice / Review / Library / Roadmap，且写明「Web MVP 不一次开放六个一级导航」——而侧栏现在**已经是 6 项**（`AppShell.tsx:73-79`：对话/练习/复习/知识地图/笔记/资料库），加第 7 项超出既定 IA。更关键的是「笔记」那次的先例是**完全没有入口**（P5G.5：新建按钮从未接线），而题库有三个入口，不属于该情形。题库与练习共用同一套筛选上下文，放同页最省跳转；日后若确为高频目的地，再升一级是廉价动作。

### D7 导入导出 → **A：本轮不做 QTI；做备份/恢复 + Markdown 导出**

1. **本地备份 / 恢复**：题库本就在 SQLite 里，随资料库与应用数据一起备份（对齐 `PROJECT_GUIDE.md` P5G 补充规划里的「数据备份 / 恢复专项」——那里称它是本地优先产品用户信任的根基）；
2. **Markdown 导出**：复用已有通道 `tools/obsidian_export.py` 的 `obsidian_export_quiz_summary`（已在导出错题与薄弱点）。

**QTI 留作后续**。理由：QTI 是为「跨系统交换」存在的，而本项目当前没有交换对象（不分享、不接 LMS）；已有导出通道是 Markdown，零新格式即可满足「把错题带走看」。真正的风险是**丢数据**而不是「别的系统读不了」。导入侧更晚且会被 D9 咬住——外部导入的题**没有本地原文快照**，直接进库会破坏证据链，需要先设计「外部题如何标注 attribution」（很可能进「待核实」而非当本地题）。B/C 的成本被低估：QTI 有 1.2 / 2.x / 3.0 多版本与大量题型/元数据分支，实现+测试可能超过本轮其它项之和。

### D8 数据模型与迁移 → **A：一列 + 两张小表，状态全部派生**

- questions **加 1 列**做收藏（bookmarked_at，空串=未收藏）；
- **新增 2 张小表**承载命名练习集：question_sets(id, name, created_at) 与 question_set_items(set_id, question_id, position)，**只存 id，不复制题面**；
- **「错题 / 未作答 / 已作答」全部派生**（join quiz_attempts 判断），**不物化**；
- 迁移沿用 `quiz/store.py::_ensure_db` 的幂等 PRAGMA 迁移（与 E15 的 verdict 列同款；`core/db.py` 的 `ensure_columns` 是同类助手，但题库这条线此前未使用，本次不为迁移单独重构）。

理由：题在 questions、作答在 quiz_attempts，「状态」是查询结果，永远不会与事实失同步（该库现状：17 题、每题恰好一次作答，状态本来就能推出）。迁移最小且可回滚，现有题目零迁移。C（物化 wrong_count / last_verdict 等）一旦漏更新就是永久不一致，而题库量级不值得为速度付此代价；B 是第二份真相；D 是提前泛化（标签已被 D2 否掉、QTI 已被 D7 排后）。本次不触碰 document_id / source 的路径派生（属 E17）。

## 6. 验收条件（整体）

**用户能做到**：

1. 看到**所有生成过的题**，并按状态（未作答/已作答/错题/已收藏）、概念、资料、题型、难度筛选；
2. 收藏与取消收藏；一键练「错题 / 收藏 / 当前筛选结果」；
3. 在复习页看到**完整的**错题集（不再被 20 条截断）；
4. 在对话里问「我收藏了多少题」「哪个概念错得最多」「我还有哪些没做」，并点某道题「问 AI」得到讲解。

**边界必须成立**：

- 错题 = 该题**最近一次作答 verdict 为 incorrect**；partial **不算**；重练答对后**自动脱离**；
- **收藏不进入复习队列**，今日队列仍由掌握度引擎按概念计算；
- **掌握度只记在已审查概念上**；联网题引出的新概念**只进候选**；
- 联网题必须带**来源快照**且界面**可点回原文**；
- **单一真相源**：无物化状态列；题库不复制题面。

**工程约束**：迁移幂等、旧数据零丢失；store/服务层单测 + 路由契约测试；浏览器层用确定性 mock 复现一次「收藏 → 组卷 → 练习」流程（沿用 `web/frontend/e2e/interaction.spec.ts` 的写法）。

## 9. 交付后的实测口径（2026-09-10）

- 「错题」在**复习队列**与**题库筛选**里由同一个谓词定义：该题**最近一次**作答的 verdict 为 `incorrect`（`quiz/store.py` 的 `_WRONG_VERDICT_SQL` + `MAX(id)` 子查询）。`partial` 不算错。
- **这是本次唯一有意的用户可见语义变更**：以前「错题本」收的是*所有*答错过的尝试，现在只收*最近一次仍答错*的题——重练答对后会从错题里消失。复习调度（SM-2）不受影响。
- 未作答的题在题库列表与 `bank_list` 工具里都**不返回 `answer` / `explanation`**，所以题库不会变成答案表。

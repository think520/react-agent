# 知识地图设计决策文档

本文记录 P5E.6 知识地图产品重置的全部设计决策，来源于两轮结构化追问（Q21–Q64）。每条决策均附有选择理由，可直接用于实现参考与评审。

---

## 1. 产品定位

知识地图不是 Wiki 编辑器，不是 AI 知识库后台，也不是全库自动化图谱生成系统。

它的职责分工如下：

```
Chat         → 提问、全库检索、基于原始资料回答
知识地图      → 浏览主题和概念关系、定位原文、补充个人笔记
资料卡        → 查看一份原始资料的目录、检索状态、关联概念、原文位置
高级维护      → 批量整理、深度解读、修复、预算和 Provider 路由（折叠，不在新手路径）
```

核心原则：**导入资料后立即可用于 Chat 和 Practice，不以"没有知识地图"作为阻塞状态。**

## 2. 图谱模型决策（Q21–Q41）

### 2.1 图谱类型（Q21）
采用 **C：可视化浏览为主，AI 按需提取概念和关系候选，用户确认后逐步积累为可信知识图谱。**

不做自动语义网络（未经验证的模型输出直接铺满全库）。

### 2.2 关系类型（Q22）
采用 **D：有限系统关系 + 用户自定义关系。**

系统关系（稳定，可筛选，便于 AI 检索）：
- 属于
- 前置知识
- 组成部分
- 对比
- 应用于
- 来源于

规则：
- 用户可手动补充自定义关系。
- AI 只能提出关系候选，确认后才进入正式图谱。
- 同义关系必须归一化（"组成""包含模块" → 统一为"组成部分"）。

### 2.3 关系证据来源分级（Q23）
采用 **D：四级来源分级。**

| 级别 | 定义 | 能否进入正式图谱 |
|---|---|---|
| 原文明确 | 有直接原文摘录和位置 | ✅ |
| 跨资料归纳 | 由多段原文推导，显示采用证据 | ✅ |
| 用户创建 | 明确标记为个人关系 | ✅ |
| AI 推测 | 无充分证据，只有模型判断 | ❌ 只能在候选区 |

每条正式关系必须能回答：**为什么连接、依据在哪里。**

### 2.4 概念粒度三级结构（Q27）
采用 **D：三级结构 + 用户可升降级。**

| 层级 | 说明 |
|---|---|
| 主题簇 | 组织知识领域，不作为普通概念文章（例：RAG、图算法） |
| 核心概念 | 默认显示在地图中（例：Embedding、混合检索） |
| 细分概念 | 按需展开（例：滑动窗口、BM25、Rerank） |
| 普通术语 | 先作为标签，不占用图谱节点 |

AI 每次提取受数量约束：
- 核心概念：3–8 个
- 细分概念：最多 12 个
- 关系：只提交有证据的
- 其余术语保存为标签

### 2.5 原文定位精度（Q28）
采用 **D：目标段落级定位，解析器不支持时降级到章节/页面，并明确显示定位精度。**

| 格式 | 目标定位 |
|---|---|
| PDF | 页码 + 原文摘录高亮 |
| PPTX | 幻灯片 + 文本框/备注摘录 |
| DOCX | 标题路径 + 段落 |
| MD | 标题锚点 + 文本范围 |
| TXT | 行号或文本范围 |

原文变化后，旧定位标记为"可能过期"，不跳到错误内容。

### 2.6 主题簇维护（Q30）
采用 **D：用户结构做骨架，AI 只提建议。**

- 课程、文件夹、用户已有分类构成稳定骨架。
- AI 只能提出拆分、合并、重命名和跨主题关联候选。
- 一个概念只有一个主要归属，但可出现在多个主题视图中。
- 调整主题结构不复制概念，不破坏原文证据。

### 2.7 同义概念处理（Q40）
采用 **D：规范概念 + 别名 + 明确合并审查。**

- 系统提出"可能重复"候选，显示各名称、来源、定义差异和关系影响。
- 用户确认合并、保留分开或设为别名。
- 合并后旧名称仍可搜索并跳到规范概念。
- AI 不能静默合并已确认概念。

### 2.8 候选区管理（Q41）
采用 **D：候选放独立"待整理"区。**

- 可在地图中临时预览（虚线样式），但默认不参与正式关系和 Chat 检索。
- 被忽略或拒绝的候选记录抑制期，避免反复出现。
- 只有用户确认后才进入正式地图和 AI 检索。

## 3. 数据架构（Q36）

采用 **B：SQLite 为真相源，Markdown 为呈现层。**

| 层 | 职责 |
|---|---|
| 原始资料 | 事实证据真相源，AI 只读 |
| SQLite 图谱 | 概念、关系、证据定位、版本、主题归属的真相源 |
| Markdown 页面 | 用户阅读、笔记和导出的呈现层 |

规则：
- Markdown 可编辑，保存时通过明确字段更新图谱。
- 不做双向猜测同步。
- 图谱关系不从任意 Markdown 链接反推。

## 4. 前端技术选型（Q35，调研结论）

**选定 Sigma.js + Graphology。**

| 库 | 职责 |
|---|---|
| Sigma.js | WebGL 渲染大规模局部图，性能边界约 10,000 节点 |
| Graphology | 前端局部子图数据结构、布局算法和筛选状态管理 |

不选 React Flow（适合人工编排流程图，不适合增长型知识图谱）。

编辑操作走概念详情面板和关系面板，不把图谱做成流程图编辑器。

## 5. 图谱视图设计

### 5.1 规模策略（Q31）
采用 **C：数据库支持数千至上万概念，前端每次只加载 30–120 个节点。**

```
主题总览    → 只加载主题簇节点
进入主题    → 加载核心概念（约 20–40 个）
点击节点    → 查询并展开一层邻居（约 10–20 个新节点）
显示来源    → 按需加载资料节点
继续探索    → 服务端返回局部子图
```

单个视图控制在约 30–120 个节点，避免变成无法阅读的大网。

### 5.2 布局策略（Q32）
采用 **D：混合布局。**

| 场景 | 布局方式 |
|---|---|
| 全库总览 | 稳定的主题簇固定布局 |
| 主题内部 | 受约束的力导向布局 |
| 学习路线 | 层级布局（从左到右） |

规则：
- 用户拖动后保存节点位置，刷新后恢复上次视角，不重新跑布局算法。
- 布局变化只影响展示，不改变底层知识关系。
- 浏览模式和整理模式严格分开，默认进入浏览模式。

### 5.3 三视图架构（Q33）
采用 **D：同一份知识数据提供三种视图。**

| 视图 | 用途 | 默认端 |
|---|---|---|
| 地图 | 发现主题和概念关系 | 桌面 |
| 目录 | 按主题层级快速定位概念 | — |
| 来源 | 按原始资料查看关联概念和原文位置 | — |

三视图共享同一份筛选状态：地图里选了"主题：RAG"，切到目录和来源时同步筛选。

### 5.4 空状态分级展示（Q34）
采用 **D：正式索引节点立即可用，候选用虚线样式区分。**

- 主题簇、资料和章节是正式索引节点，导入后立即显示。
- 本地关键词只显示为"术语候选"，使用虚线 + 透明度 0.6。
- AI 或用户确认后，候选升级为正式概念。
- 地图明确显示"这是资料结构"还是"这是已确认知识"。

## 6. 导航与入口设计

### 6.1 主导航位置（Q45）
知识地图作为 **一级导航**，与 Chat、Practice、Review、Library 并列，名称固定为"知识地图"。

空状态主按钮：**"去资料库选择资料"**，不在知识地图内放 AI 动作入口。

### 6.2 与 Library 的关系（Q44）
Library 只承担资料管理和资料卡，点击后进入独立的知识地图工作区，保留返回路径。

不把"资料管理、索引状态、图谱浏览、整理任务"塞在同一页面。

### 6.3 移动端策略
P5E.6 / P5G 阶段：**移动端不做知识地图图谱视图，只保证不崩溃和能查看资料、Chat、Practice。**

等 P5G Windows 桌面版稳定，再决定是否做 PWA 或移动端只读视图。

## 7. 资料卡设计（Q48）

采用 **D：普通视图 + 高级区。**

**普通视图（默认展示）：**
- 标题 / 文件类型 / 最近同步
- 可检索状态（complete / partial / empty / error）
- 目录或章节
- 已关联概念
- 打开原文
- 提取本资料概念

**高级区（折叠，用户展开）：**
- 提取报告（chunk 数、空白页、图片统计）
- chunk / 索引状态
- 旧 Wiki 迁移
- 重新同步
- 批量处理

## 8. 候选审查 UX（Q49 + Q64）

采用卡片组格式，每次展示 5–8 张，按置信度排序（AI 最确定的排前面）。

**卡片结构：**
```
┌─────────────────────────────────────┐
│ 概念名   [核心概念 ▼]  置信度：高    │
│ 一句定义                             │
│ 原文摘录："..." — 《资料名》第3章    │
│ 建议关系：属于 RAG / 前置 Embedding  │
│ [✓ 确认]  [合并▼]  [降为标签]  [忽略]│
└─────────────────────────────────────┘
```

**快捷键：**
- `Enter` → 确认并跳下一张
- `M` → 合并
- `L` → 降为标签
- `X` → 忽略
- `空格` → 展开/收起原文摘录

**顶部操作栏：**
- `[全部确认（置信度高）]` `[跳过本次]` `[稍后处理]`

**完成后：**
- 已确认概念立即淡入地图（约 200ms）
- 显示本次写入数量和对地图的影响摘要

关系审查策略（Q53）：普通关系随概念候选一起确认；冲突关系、跨资料归纳、影响已有概念的关系单独进入关系审查。

## 9. 交互与动效决策（Q56–Q64）

### 9.1 空状态分情况处理（Q56）

| 情况 | 展示 |
|---|---|
| 资料库为空 | 一句话说明 + 跳转到资料库导入 |
| 有资料但无概念 | 显示资料节点骨架，每张资料卡有"提取本资料概念"入口，配说明文字 |
| 有待确认候选 | 醒目入口"你有 N 个待审查概念候选"，优先引导完成审查 |

### 9.2 三视图切换（Q57）

**不做方向滑动动画，只做状态联动 + 轻量淡入（约 120ms）。**

核心设计：三视图共享选中状态。在地图里选中"RAG"，切到目录时自动滚动到 RAG 所在行，切到来源时显示与 RAG 相关的资料。用户感觉切换的是呈现方式，而不是在浏览三个不同的东西。

视图选择器固定在顶部，内容区域重绘，不做位置动画，避免小屏眩晕感。

### 9.3 图谱节点加载动效（Q58）

采用**分两步渲染**：

1. 第一帧（立即）：主题节点和核心概念节点淡入（约 200ms），位置由后端预计算，不在前端跑力导向布局
2. 第二步（+150ms）：关系边线从各节点向外延伸绘制，约 300ms，ease-out
3. 展开邻居：新节点从被点击节点位置扩散淡出，约 150ms
4. 收起分支：子节点向父节点方向收缩淡出

**节点位置由后端保存，刷新或切回时完全复原上次视角，不重新跑布局算法。**

### 9.4 概念提取过程 UX（Q59）

提取过程显示**离散阶段文字 + 三点墨迹动效**，不用横向进度条。

阶段文字：
1. "正在读取资料章节"
2. "正在识别核心概念"→ 此时开始渐进出现第一批候选预览（可点击）
3. "正在分析关系"
4. "提取完成，共 N 个候选"

规则：
- 资料卡原地显示状态变化，不锁死用户在等待页
- 用户可在任意阶段取消，已识别候选保留
- 完成后按钮变为"查看候选（N 个）"

### 9.5 图谱视觉语言（Q60）

从 `docs/DESIGN.md` 的 token 延伸，不使用科技蓝黑、荧光或发光效果。

**背景：** `--color-parchment`（#F3EFE5）

**节点样式：**

| 节点类型 | 背景 | 边框 | 文字 |
|---|---|---|---|
| 主题簇 | `--color-ink-blue` 填充 | 无 | `--color-paper-soft` 白色 |
| 核心概念 | `--color-paper-soft` | `--color-ink-blue` 实线 | `--color-ink` |
| 细分概念 | 同上但更小 | 同上但更细 | `--color-muted` |
| 资料来源 | 透明 | `--color-wheat` 描边 | `--color-muted`，文档图标 |
| 候选/未确认 | 透明度 0.6 | 虚线 | `--color-faint` |

**边线样式：**

| 来源级别 | 线型 | 颜色 |
|---|---|---|
| 原文明确 | 实线 | `--color-ink-blue-faint` |
| 跨资料归纳 | 虚线 | `--color-ink-blue-faint` |
| 用户创建 | 实线 | `--color-sage-soft` |
| 候选/AI推测 | 点线，透明度 0.5 | `--color-ink-blue-faint` |

**悬停效果：**
- 节点背景加深一级，边框变为 `--color-ink-blue-soft`，关联边线同步高亮
- 约 100ms 颜色过渡，**无缩放、无弹跳**

**颜色语义：**
- 颜色只表示主题归属，不作为来源或正确性的唯一表达
- 节点形状区分概念与资料来源
- 边线样式区分关系证据级别
- 关系名称在选中边或放大后显示，不默认堆满画面

### 9.6 节点详情侧栏（Q61）

单击节点 → 侧栏从右推入（约 180ms，ease-out），图谱整体左移（不重算节点位置）。
关闭 → Esc 或点击图谱空白处，侧栏向右滑出，图谱恢复原宽度（约 150ms）。

**侧栏固定结构：**
```
── 概念名称  [编辑]  [查看完整页面 →]
── 一句定义（可折叠展开）
── 关系 ──────────────────────────────
   属于：RAG
   前置知识：Embedding
   组成部分：Retriever, Reranker
── 原文摘录 ──────────────────────────
   "..." — 《资料名》第3章  [跳转原文]
   "..." — 《资料名2》第7页  [跳转原文]
── 个人笔记 ──────────────────────────
   [点击添加笔记...]
── 掌握状态 ──────────────────────────
   学习中  |  错题：2  |  上次练习：3天前
   [生成练习题]
```

### 9.7 搜索与筛选（Q62）

**呼出方式：** `Cmd/Ctrl+K`

**搜索效果：**
- 匹配节点保持原样
- 不匹配节点透明度降到 0.15
- 关系边线只显示匹配节点之间的关系
- 键盘上下选择，Enter 定位并居中该节点
- Esc 清除搜索状态，图谱完全恢复

**筛选 chip（搜索框右侧）：**
```
[全部] [核心概念] [细分概念] [资料] [候选]
[主题：RAG] [主题：算法]  ← 动态生成当前资料库主题簇
```

**重要规则：** 筛选状态持久，切换三视图时目录和来源同步筛选，不会因切视图而丢失当前关注点。

### 9.8 Chat ↔ 知识地图双向深链（Q63）

**Chat → 知识地图：**
- 已确认概念在回答中显示为 `#概念名` chip
- 悬停显示：一句定义 + 掌握状态
- 点击：在右侧面板或浮层打开知识地图，居中定位该节点（不离开 Chat）
- 候选概念显示为虚线 chip，悬停提示"点击审查此候选"
- 图谱内轻量标注"此概念在最近 Chat 中被讨论过"（点状标记，低视觉权重）

**知识地图 → Chat：**
- 概念详情侧栏有"去 Chat 深入"按钮
- 点击后 Chat 带上该概念作为上下文，限定在当前资料库范围内检索
- 预填内容示例："请解释 [概念名称]，结合我的资料"

## 10. 概念提取成本控制（Q39）

采用**分层成本控制**：

```
本地结构与术语候选（零模型成本）
    ↓
快速非推理模型提取概念/关系候选
    ↓
用户审查
    ↓
仅冲突、跨资料归纳、深度解读调用强模型
    ↓
相同资料指纹复用缓存
```

规则：
- 同一资料指纹不重复提取
- 快速模型处理大多数提取，强模型只处理真正困难的关系
- 每次提取受数量硬约束，不能把所有名词都塞进图谱

---

## 11. 版本历史策略（Q54）

采用 **C：轻量历史。**

- 每个概念和关系有 `revision` 字段
- 记录修改人、时间、原因、证据变化
- 支持查看历史摘要和撤销最近一次修改
- 不做完整时间旅行 UI

---

## 12. 与 Practice / Review 的集成（Q55）

采用 **C：参与，但只能使用已确认概念与原文证据。**

- Practice 可按概念生成题目
- Review 可把薄弱点挂到概念节点
- 错题和掌握度可显示在概念详情侧栏
- 正式题目仍必须引用原文或网页证据
- 知识地图不能替代原文证据直接作为出题依据

## 13. 前端优化建议

以下是基于上述决策提炼的前端实现优化方向，供实现时参考。

### 13.1 渲染性能

**虚拟化与局部加载：**
- 永远只渲染当前视口附近的节点，Sigma.js 的 WebGL canvas 天然支持大量节点但仍需分页加载
- 后端 API 返回局部子图（节点 + 边），前端不持有完整图谱
- 节点位置由后端保存并返回，前端不做实时力导向计算（首次布局例外，由后端计算后持久化）

**避免的性能陷阱：**
- 不在 React 渲染树中放图谱节点（用 Sigma.js 的 canvas 渲染，不用 SVG/DOM）
- 筛选时不重新请求后端，用 Graphology 的前端子图过滤
- 候选审查卡片列表用虚拟滚动（候选可能有几十张）

### 13.2 动效原则

所有动效必须符合 `docs/DESIGN.md` 第 11 节：

| 场景 | 时长 | 属性 | 缓动 |
|---|---|---|---|
| 视图切换淡入 | 120ms | opacity | ease-out |
| 核心节点出现 | 200ms | opacity | ease-out |
| 边线绘制 | 300ms | stroke-dashoffset | ease-out |
| 展开邻居 | 150ms | opacity + transform | ease-out |
| 侧栏推入 | 180ms | transform | ease-out |
| 侧栏关闭 | 150ms | transform | ease-in |
| 节点悬停 | 100ms | background/border | ease-out |
| 候选淡入地图 | 200ms | opacity | ease-out |

**严格禁止：**
- 弹跳（spring/bounce）
- 节点缩放（scale）
- 横向进度条（容易被理解为完成百分比）
- `transition: all`
- 自动循环动画

`prefers-reduced-motion` 下：取消所有位移和 opacity 动效，保留必要的颜色状态反馈。

### 13.3 交互细节优化

**图谱空白区域的手势：**
- 滚轮/双指缩放：调整缩放级别（Sigma.js 原生支持）
- 拖拽空白处：平移视口
- 单击空白处：关闭侧栏
- 双指缩放到很小时：自动切换为"主题簇总览"模式，显示更少节点

**键盘支持（图谱聚焦时）：**
- `Cmd/Ctrl+K`：呼出搜索
- `Escape`：关闭侧栏 / 清除搜索
- `Tab`：在可见节点间循环聚焦
- `Enter`：打开当前聚焦节点的侧栏
- `方向键`：从当前节点沿关系移动到相邻节点

**侧栏内的交互：**
- 个人笔记支持 Markdown 编辑，点击空白处自动保存
- 关系列表每条可点击，跳转到对应节点（图谱居中该节点）
- 原文摘录过长时截断显示，点击展开

### 13.4 空状态与错误状态

| 状态 | 处理方式 |
|---|---|
| 图谱加载超时（> 5s） | 显示已加载的节点，提示"部分内容加载中"，不整页 loading |
| 局部子图加载失败 | 该节点显示"加载失败 [重试]"，不影响其他已渲染节点 |
| 概念提取失败 | 资料卡显示具体原因 + 重试按钮，不用整页错误覆盖 |
| 候选写入失败 | 已确认候选保留，显示失败原因 + 重试，不丢失用户操作 |
| 无网络时的 Chat #chip | 概念 chip 仍可渲染，点击时提示"知识地图暂时不可用" |

### 13.5 骨架屏策略

图谱的 skeleton 必须匹配最终渲染尺寸，不能加载完成后大幅跳动：

- 主题簇节点用固定大小的圆角矩形占位
- 核心概念节点用更小的圆角矩形
- 边线用轻细线连接占位节点
- 骨架颜色使用 `--color-parchment` 和 `--color-ink-blue-wash` 交替

# 用户体验深度审查（2026-08-01）

> 日期：2026-08-01
> 状态：审查完成，修复进行中（分支 `fix/experience-review-2026-08-01`）
> 方法：真实运行后端 + 前端，以用户身份走完完整旅程（库状态 → 检索 → Chat → 练习 → 批改 → 错题本 → 复习队列 → 知识地图）；另派 4 个并行审计 agent 从前端交互、学习闭环、知识地图、计划书四个维度通读代码。

## 1. 总体判断

核心学习闭环**真实可用**，证据门禁、降级透明、失败恢复是突出优点；但存在 4 个会卡住普通用户的问题、一批"产品承诺了但 UI 看不见"的断层，以及知识地图大量"已规划未实现"。发布前的关键不在加功能，在**把已有能力的可见性补齐**。

### 1.1 真实体验感受

- 回答诚实：问"Dijkstra 为什么不能处理负权边"，回答明确区分"你资料里有的结论"和"资料没覆盖的原理"，然后请求联网确认——不会拿 AI 常识冒充用户资料。
- 选择题批改 0.1 秒即时；简答题约 3 秒 LLM 批改且反馈有质量（指出答案缺什么）。
- 工具过程有噪音：Agent 第一步 `read_file` 即失败（约 7µs 异常），随后连续检索 3 次才回答；展开过程面板会看到一次无原因的"处理失败"。
- 文档列表里同一课程文件标题重复出现（65 份列表 vs 68 文件），用户无法区分是子目录同名还是重复导入。

## 2. 真实运行发现的系统级问题

1. `read_file` 工具每次先失败（疑似安全边界拒绝路径）→ 降级 RAG，用户看到无原因"处理失败"噪音。
2. 同一课程文档在列表中重复显示（65 份列表 vs 68 文件）——需确认是子目录同名还是重复索引。
3. 生成练习约 26 秒无进度反馈（3 题）；批改响应完整（is_correct/feedback/explanation/concepts/attribution/mastery_changes/progress）。
4. `mastery_changes`/`progress` 后端每次答题都返回，但前端 `AnswerResult` 直接丢弃。
5. 复习队列、错题本、知识地图状态（49 概念/30 关系/0 候选）均正常。

## 3. 可优化的功能（按用户被卡住程度分级）

### 3.1 P0 阻断

| # | 问题 | 用户感受 | 说明 |
|---|---|---|---|
| 1 | 会话内几乎所有操作失败静默无反馈（切模型、确认记忆、设置变更、联网选择、Wiki 系列——`setError` 后在会话视图无处渲染） | 点了"确认记住"毫无反应 | 违背"反馈引导行动"原则，改动小（挂全局错误位） |
| 2 | 新建资料库必须手打绝对路径，无目录选择器 | 新手第一次被要求输入 `D:\Learning` 直接卡死 | Web 端受浏览器限制，合理降级：默认路径预填 + 解释"为什么需要一个文件夹" |
| 3 | 错题复习对部分题是死路：变式题强依赖原题 `chunk_id`，但联网题、旧题、重同步后的题没有 chunk → 永远失败，无回退、无原因 | 复习队列里躺着永远点不开的错题 | 加回退链（无 chunk → 按概念重新出题 → 最后原题重练）+ 失败原因上屏 |
| 4 | 知识地图提取计时归零 + 后端重启任务永久卡死（07-27 增量设计文档已规划，未实现） | 关面板再开以为任务重跑；重启后永动 spinner | 服务端 `started_at` + 启动时孤儿 `running` 标记 `interrupted` |

### 3.2 P1 明显摩擦

| # | 问题 | 建议 |
|---|---|---|
| 5 | 掌握度是核心承诺但 UI 完全不可见：后端返回 `mastery_changes`，前端丢弃；概念侧栏"掌握状态"是写死的"尚未练习" | 答完题显示一行"知识点 X：掌握度 +0.1 → 学习中"；概念侧栏接真实数据 |
| 6 | 复习=原题重放：到期复习直接复用历史题目，与"错题才走变式"不一致，无"你以前做过"标记 | 到期复习走变式或标注"复习题·曾答错" |
| 7 | 停止生成无收尾：半截回答被当完整回答展示，无"已停止"标记、不能续写 | 加"生成已停止"状态 + 明确重发入口 |

| 11 | 知识地图零编辑入口：后端全套 CRUD API 存在但前端零调用 | 小步开放：侧栏编辑名称/定义/层级 + 删除带受影响关系数确认 |
| 12 | 新确认的概念落在原点附近随机位置，与已整理布局脱节 | 确认候选后返回坐标 + 前端高亮数秒 |

## 4. 学习闭环审计发现

### P0

- **错题变式死路**（见 3.1#3）：`generate_wrong_answer_variant` 强依赖原题 `chunk_id`；联网题（source 只有 `snapshot_id`）、旧题（证据可空）、重同步后 chunk 失效的题全部命中 `evidence_missing` / `variant_generation_failed`。

### P1

- 到期描述显示原始英文状态（`mastered`/`learning`/`needs_review`），且 `get_due_reviews` 连 `mastered` 也纳入到期——"已掌握"+"到期"自相矛盾，无"下次复习时间"解释。
- SM-2 全链路对 UI 用户不可见（间隔、`next_review`、`interval_days` 只在 CLI 暴露）。
- 到期复习原题重放（见 3.2#6）。
- "问 AI"每次新建聊天会话（见 3.2#9）。
- 简答批改二值化（见 3.2#10）。

### P2

- Chat 里"生成 5 道练习"按钮实际是两步（预填话题，需再点一次生成）。
- 创建练习无题量/题型/难度控制（CLI 有，Web 固定 5 题）。
- 放弃练习后已提交答案无处查看（但会进错题本）。
- 错题复习一次一题，连刷多条要来回跳转。
- 完成页只说"答对 X/Y 题"，无逐题回顾。

## 6. 计划书覆盖评估

**结论：覆盖完整且诚实，精度不足。**

- P5C–P5E.6"已完成"声明经代码抽查全部属实（Python 1169 / Vitest 19 与声称一致）。
- P5G 全部未动工（文档自我声明一致）——最大风险：**PyMuPDF（AGPL）仍在线上**，P5G.0 移除是发布第一道门槛。
- 计划缺口（应补、不属于"明确不做"）：

1. **数据备份/恢复专项**——备份对象清单（资料库、personal-knowledge.db、usage.db、research.db、preferences）、WAL 一致性、恢复 UI、卸载时数据保留契约。
2. **复习提醒交付机制**——Windows 通知 vs 托盘常驻，不常驻则提醒无法送达。
3. **应用升级路径**——安装器覆盖行为、数据目录版本检测、升级前备份提示（自动更新可延后，升级动作必须规划）。
4. **卸载清理与数据保留策略**——NSIS 卸载器行为契约。
5. **桌面环境适配与性能预算**——DPI/高分屏/多显示器验收项、首启时间、包体积目标。

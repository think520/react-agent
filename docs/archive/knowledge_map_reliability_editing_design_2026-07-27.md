# 知识地图可靠性、编辑能力与跨文档联动设计

> 日期：2026-07-27  
> 状态：产品决策已确认，等待分阶段实现  
> 关系：本文是 [`knowledge_map_design.md`](knowledge_map_design.md) 的增量规格；冲突处以本文为准。

## 1. 目标

本轮不重新定义知识地图的产品定位，而是修复已经暴露的四类核心问题：

1. 概念提取耗时长，关闭面板再打开后计时归零，用户无法判断任务是否重跑、卡死或仍在继续。
2. 图谱布局拥挤、断开子图散落、标签和连线互相遮挡，整理布局缺少稳定性和物理反馈。
3. 不同文章提取出的概念只在名称完全一致时复用节点，不会主动发现跨文档关系。
4. 后端虽然已有部分概念和关系 CRUD，前端却没有向用户提供完整的新增、编辑、删除、来源管理和恢复入口。

目标体验：

```text
可靠提取
→ 用户确认概念
→ 图谱立即可用
→ 后台寻找跨文档关系和重复节点
→ 用户审查关系 / 合并候选
→ 用户可随时编辑、删除、恢复和追踪变更
```

## 2. 当前实现诊断

### 2.1 重新打开后计时归零

`concept_extraction_runs` 已经持久化任务状态，同一文档存在 `queued` 或 `running` 任务时，后端不会重复创建任务。因此在后端进程仍然存活时，重新打开面板通常只是前端计时归零，不是重新提取。

当前前端使用组件内 `elapsedSeconds = 0` 开始计时，没有根据服务端 `started_at` 计算真实耗时。这会制造任务重启的错觉。

更严重的边界是：当前任务通过 FastAPI 进程内 `BackgroundTasks` 执行。关闭面板或浏览器不会中断任务，但后端重启会销毁执行线程；数据库可能仍停留在 `running`，且启动后不会自动续跑。

### 2.2 提取耗时过长

当前章节概念扫描、章节内关系分析和跨章节关系分析大多串行调用模型。章节较多时，请求数线性增长，用户可能等待 5–10 分钟。

### 2.3 跨文档关系缺失

当前提取器只接收当前文章内容：

```text
当前文章章节扫描
→ 当前文章内部关系分析
→ 当前文章跨章节关系分析
```

确认候选时只按名称精确匹配已有概念。新文章中的“智能体”和旧文章中的“大模型”名称不同，模型没有看到旧图谱和旧证据，因此不会提出跨文档关系。

### 2.4 布局杂乱

当前“整理布局”只同步执行固定次数的 ForceAtlas2：

- 没有社区检测。
- 没有连通分量打包。
- 没有节点和标签防碰撞的收尾阶段。
- 坐标直接跳变，只有相机复位动画。
- 孤立节点随机散落在主画布。
- 标签固定绘制在节点右侧，密集区域容易覆盖。

拖动节点和位置保存已经存在，但缺乏连接手柄、固定状态、局部避让和明确反馈，用户难以感知可拖动性。

### 2.5 用户 CRUD 缺失

后端已经提供概念新增、编辑、删除和关系新增、删除 API。前端目前主要开放个人笔记编辑，没有完整暴露节点 CRUD、关系 CRUD、来源管理、回收站和变更历史。

## 3. 总体原则

1. **概念提取和跨文档关系分析解耦。** 概念确认不等待全图关系补全。
2. **候选先审查。** 跨文档关系和近义节点合并都不能自动写入正式图谱。
3. **结构与证据分级。** AI 推断关系可以进入已审查结构，但不能冒充原文明示关系。
4. **图谱归用户所有。** 用户拥有完整的新增、编辑、删除、来源管理、撤销和恢复能力。
5. **默认渐进展示。** 主画布表达已有结构，孤立节点和细节节点按需出现。
6. **修改可追溯。** 用户、Agent、迁移和候选确认产生的变更都写入持久化历史。
7. **本轮只验收桌面端。** 不新增移动端实现或移动端测试要求。

## 4. P0：可信提取

### 4.1 持久化任务与章节断点

新增章节级持久化记录，例如：

```text
concept_extraction_sections
  run_id
  section_index
  section_title
  chunk_id
  content_hash
  status              queued | running | completed | failed
  attempt_count
  result_json
  error
  started_at
  completed_at
```

任务重启规则：

- 已完成且 `content_hash` 未变化的章节直接复用。
- `queued`、中断的 `running` 和调用异常的章节进入恢复队列。
- 单章节调用异常最多自动重试 1 次。
- 正常返回但质量偏低不视为章节失败，交给质量门禁处理。
- 文档内容版本变化后，不复用 hash 已变化的章节结果。

后端启动时扫描没有有效执行租约的 `queued/running` 任务，恢复未完成章节。不能继续依赖单次 HTTP 请求绑定的 `BackgroundTasks` 作为持久任务执行器。

### 4.2 服务端真实时间

提取任务至少保存：

```text
created_at
started_at
updated_at
completed_at
heartbeat_at
```

前端展示时间使用服务端时间计算：

```text
elapsed = server_now - started_at
```

关闭面板、切换页面、刷新浏览器或重新打开应用后，计时不能归零。后端重启恢复任务时，仍显示任务第一次开始时间，同时单独记录恢复次数。

### 4.3 状态机

```text
queued
→ scanning_sections
→ merging_concepts
→ analyzing_local_relationships
→ analyzing_cross_section_relationships
→ quality_check
→ supplementing（最多一次）
→ ready_for_review
```

异常状态：

```text
paused_rate_limit
interrupted
failed
cancelled
completed_with_warnings
```

界面不得只显示“已等待 N 秒”，还要显示：

- 已完成章节数 / 总章节数。
- 当前阶段。
- 已识别概念数。
- 当前是否重试、限流或恢复。
- 预计剩余时间；样本不足时明确显示“暂无法估算”。

示例：

```text
已完成 8/10 章 · 已识别 21 个概念
第 6 章正在重试 · 预计剩余约 48 秒
任务已运行 2 分 12 秒
```

### 4.4 并发与时间目标

- 普通 8–12 章节课程文档目标在 3 分钟内进入候选审查。
- 章节概念扫描最多 3 路并发。
- Provider 出现限流时自动降低为 2 路或 1 路。
- 并发只改变执行时间，不重复发送相同章节，不增加设计上的提取次数。
- 关系补全和质量补提仍受“最多一次定向补提”约束。
- 关闭进度窗口只关闭界面，不取消任务。

### 4.5 重复提取保护

- 相同 `document_id + content_version` 已存在活动任务时，返回原 `run_id`。
- 相同内容已经完成且用户未选择“重新提取”时，不创建新任务。
- “重新提取”放在更多菜单并二次确认。
- 资料列表持续显示：未提取、提取中、待审查、已完成、有警告、失败。

## 5. P1：可用、可编辑的知识地图

### 5.1 两级布局

采用“全局聚类 + 局部聚焦”两级模型。

全局视图：

1. 按连通分量拆分子图。
2. 对有结构的子图执行社区检测。
3. 社区内部使用受约束力导向布局。
4. 执行节点防重叠和标签避让。
5. 对各子图进行矩形打包，避免互相覆盖。
6. 使用稳定种子和已保存位置，避免每次打开重新洗牌。

局部视图：

- 点击节点后将其平滑移动到视觉中心。
- 一跳邻居进入内圈，二跳邻居进入外圈。
- 无关节点淡化或暂时隐藏。
- 一键返回全局视图并恢复原位置。

“整理布局”只改变展示位置，不修改知识关系。

### 5.2 动效与拖动

- 布局在后台或 Worker 中计算，完成后用约 500ms 过渡到新坐标。
- 拖动节点时连线实时跟随。
- 与当前节点直接相连的一跳邻居轻微避让。
- 松手后仅在一跳邻域运行约 300–450ms 的局部稳定过程。
- 不因拖动一个节点重新启动整张图的物理模拟。
- 新节点缩放、淡入，随后绘制新关系线。
- 用户手动位置持久化；整理布局前可创建位置检查点。
- “减少动效”开启时改为短淡入或直接完成。

### 5.3 孤立节点

没有任何正式关系的节点不进入主画布，统一进入“待连接概念”区域。

支持操作：

- 让 AI 寻找可能关系。
- 手动建立关系。
- 提交合并候选。
- 删除节点。
- 降级为标签。

主画布显示待连接数量，不静默丢弃节点。

### 5.4 标签和连线

- 全局视图默认不常驻显示关系文字。
- 悬停连线时显示关系类型、方向和证据等级。
- 选中节点时显示其一跳关系文字，其他边淡化。
- 关系标签必须避让节点名称。
- 多条同向或反向连接使用曲线或分轨，避免完全重叠。
- 原文明示关系使用实线。
- 已审查的跨资料推断关系使用虚线。
- 用户关系使用独立但克制的颜色或线型。

### 5.5 浏览模式与编辑模式

默认进入浏览模式。顶部提供明确的“编辑图谱”开关。

编辑模式开启后：

- 双击空白处创建节点。
- 节点显示连接手柄。
- 可拖线创建关系。
- 选中节点后显示编辑、删除和来源管理。
- 顶部显示撤销、重做和退出编辑。

浏览模式下不显示破坏性工具，避免拖动画布、拖动节点和拉线之间产生冲突。

### 5.6 用户概念

用户可以创建不绑定来源的正式概念。字段包括：

```text
名称
一句话定义
层级：主题簇 | 核心概念 | 细分概念
别名
来源：可选
个人笔记
```

无来源节点明确标记为“用户概念”。它可以参与浏览和用户关系，但不能满足 Chat 的原文证据门禁。

### 5.7 关系 CRUD

同时支持两种创建方式：

1. 从节点连接手柄拖到目标节点。
2. 在详情面板中搜索目标节点并添加关系。

创建关系时填写：

```text
起点
终点
关系类型
方向
依据类型：我的判断 | 原文明确 | 跨资料推断
备注：可选
```

详情面板的每条关系提供编辑、反转方向和删除操作。用户关系不能伪装成原文证据。

### 5.8 节点删除与回收站

- 删除节点前展示受影响的关系数和来源关联数。
- 确认后节点立即从画布移除，并进入知识地图回收站。
- 相关关系和证据随节点进入回收状态，不做不可恢复的即时物理删除。
- 30 天内可以恢复。
- 默认只抑制该节点在原来源中的再次生成。
- 删除对话框提供可选项：“在所有资料中不再建议此概念”。
- 全局抑制不是默认行为。

### 5.9 来源删除

“删除节点”和“移除来源”必须是两个独立操作。

- 节点仍有其他来源时，只移除选中的来源关联。
- 删除最后一个来源时，弹出选择：
  - 保留为用户概念。
  - 同时将节点移入回收站。
- 移除来源后，相应证据不再满足 Chat 证据门禁。
- 不允许静默删除同时被其他资料支持的共享概念。

### 5.10 持久化变更历史

所有图谱修改写入事件历史：

```text
graph_mutation_events
  event_id
  actor_type          user | agent | migration | candidate_review
  actor_id
  action_type
  entity_type
  entity_id
  before_json
  after_json
  created_at
  reverted_at
  revert_event_id
```

覆盖范围：

- 新增、编辑和删除节点。
- 新增、编辑和删除关系。
- 移除或恢复来源。
- 节点合并和拆回。
- 候选确认、拒绝和降级。
- 旧图谱迁移。

界面提供“最近修改”和“撤销此操作”。历史跨页面刷新和后端重启保留。

## 6. P2：跨文档关系与合并智能

### 6.1 触发时机

概念候选确认后，自动创建独立的跨文档关系分析任务。

- 不阻塞概念提取完成。
- 不阻塞用户查看新节点。
- 任务完成后显示“发现 N 条跨资料关系候选”。
- 更多菜单保留“重新分析跨资料关系”。
- 模型或规则升级后可以重新分析，但必须二次确认。

### 6.2 候选召回

不能把整张图谱直接塞给模型，也不能对全部节点做两两比较。

每个新确认概念只召回最相关的 5–10 个已审查旧概念，召回信号包括：

- 名称和别名精确匹配。
- CJK 2-gram / FTS 相似度。
- 可选向量相似度。
- 已有图谱邻域和主题距离。
- 双方来源中的关键 excerpt。

召回只负责缩小候选集，不直接创建关系。

### 6.3 LLM 判断

模型输入：

```text
新概念定义与证据
候选旧概念定义与证据
允许的关系类型
方向约束
```

模型输出结构化关系候选：

```text
from_id
to_id
rel_type
confidence
inference_reason
source_evidence_a
source_evidence_b
```

关系必须关联双方证据。没有双方证据时只能作为低质量建议，不能进入正式关系审查主列表。

### 6.4 两类正式关系

| 类型 | 展示 | Chat 证据效力 |
|---|---|---|
| 原文明示关系 | 实线 | 可作为来源证据，但仍需保留有效位置 |
| 已审查跨资料推断 | 虚线 | 只作为结构参考，不能单独满足原文证据门禁 |

已有 `evidence_level="cross"` 用于已审查跨资料推断；未审查的模型输出仍保存在候选表，不直接写入 `relationships`。

### 6.5 关系审查工作台

跨文档关系使用居中的知识审查工作台，不使用底部抽屉。

布局：

```text
┌──────────────────────────────────────────────────────┐
│ 大模型  ── 组成部分？ ──>  智能体                   │
├──────────────────────┬───────────────────────────────┤
│ 来源 A 原文与定位     │ 来源 B 原文与定位             │
├──────────────────────┴───────────────────────────────┤
│ AI 推断理由                                            │
│ [确认] [修改类型] [反转方向] [拒绝] [稍后处理]        │
└──────────────────────────────────────────────────────┘
```

- 背景图高亮两端节点和已有路径。
- 工作台可最小化，后台任务继续。
- 关闭或切换页面后恢复当前审查位置。
- 支持批量确认，但不能自动确认高置信度关系。

### 6.6 合并候选

模型发现近义节点时，只生成合并候选，不自动合并。

审查内容：

- 建议保留的规范名称。
- 双方定义、来源和个人笔记。
- 合并后迁移的关系数量。
- 重复关系、方向冲突和来源冲突。
- 合并后的别名列表。

确认后：

- 保留一个规范概念 ID。
- 旧名称进入别名。
- 合并来源、关系和笔记。
- 重复关系去重，冲突关系保留待处理标记。
- 整次合并可从变更历史撤销。

### 6.7 模型配置

- 跨文档关系和合并判断默认继承“概念提取模型”。
- 使用与提取一致的低温度配置。
- 高级设置允许单独覆盖关系分析模型。
- 模型不可用时任务明确失败并保留已完成结果。
- 不允许静默切换到较弱模型。
- 不占用或跟随当前 Chat 会话模型。

## 8. 分阶段实施与验收

### P0：可信提取

实现：

- 章节级断点和持久化执行器。
- 后端重启自动恢复。
- 服务端真实计时与详细进度。
- 最多 3 路自适应并发。
- 重复提取保护。

验收：

1. 提取到一半关闭浏览器，重新打开后 run ID、阶段、章节进度和真实耗时不变。
2. 提取到一半重启后端，任务从未完成章节继续，不重跑成功章节。
3. 同一文档重复点击提取不会产生两个活动任务。
4. 8–12 章节普通文档在正常 Provider 条件下目标 3 分钟内进入待审查。
5. 单章节异常最多重试一次，其余章节结果不丢失。

### P1：可用图谱

实现：

- 全局社区布局与局部径向聚焦。
- 防碰撞、子图打包、按需关系标签。
- 局部拖动物理反馈和过渡动效。
- 待连接概念区域。
- 浏览 / 编辑模式。
- 完整节点、关系和来源 CRUD。
- 回收站、来源级抑制和持久化变更历史。

验收：

1. 断开的知识社区不会重叠，孤立节点不散落在主图。
2. 点击节点后只突出一跳和二跳结构，可返回稳定全局位置。
3. 节点名称和关系标签在常见桌面视口下不互相覆盖。
4. 用户可以创建、编辑、删除、恢复节点和关系。
5. 删除最后一个来源时必须让用户选择保留为用户概念或删除节点。
6. 页面刷新和后端重启后仍能撤销历史操作。

### P2：智能联动

实现：

- 概念确认后的异步跨文档候选任务。
- Top-K 旧概念召回与证据配对。
- 关系候选和合并候选。
- 居中知识审查工作台。
- 已审查跨资料推断关系的虚线展示和证据门禁限制。

验收：

1. 分别从两篇文章提取“大模型”和“智能体”后，系统能产生有双方证据的关系候选。
2. 跨文档分析不延迟概念候选进入审查。
3. 未确认关系和合并候选不进入 Agent 正式查询结果。
4. 已确认推断关系可以用于图谱浏览，但不能独立满足 Chat 原文证据门禁。
5. `Agent / 智能体` 等近义节点只生成合并候选，不自动合并。

## 9. 不做事项

- 不恢复 Neo4j 作为运行时图谱后端。
- 不让模型直接生成 SQL 或任意图查询。
- 不对全图节点做 O(n²) 的 LLM 关系判断。
- 不自动确认跨文档关系或节点合并。
- 不让未经审查的候选参与 Chat 回答。
- 不用用户关系或 AI 推断关系替代原始资料证据。
- 不把移动端知识图谱适配纳入本轮验收。
- 不为了动效让整张图持续漂移或破坏用户保存的位置。

## 10. 已确认决策摘要

| 主题 | 决策 |
|---|---|
| 后端重启 | 按章节断点续扫 |
| 重新打开计时 | 使用服务端真实开始时间，不归零 |
| 跨文档关系 | 全部进入候选审查 |
| AI 推断关系 | 允许进入已审查结构，虚线显示，不满足证据门禁 |
| 触发时机 | 概念确认后独立后台运行 |
| 布局 | 全局社区聚类 + 局部径向聚焦 |
| 拖动 | 当前节点跟手，一跳邻居局部避让 |
| 关系标签 | 悬停或选中时显示 |
| 孤立节点 | 进入“待连接概念”区域 |
| 删除节点 | 进入 30 天回收站 |
| 删除后抑制 | 默认只抑制原来源，可选择全局抑制 |
| 删除最后来源 | 选择保留为用户概念或同时删除节点 |
| 手动关系 | 画布拖线 + 详情面板两种方式 |
| 手动节点 | 允许无来源的用户概念 |
| 编辑入口 | 默认浏览，显式开启编辑模式 |
| 关系审查 | 居中知识审查工作台 |
| 近义节点 | 只生成合并候选 |
| 模型配置 | 默认继承概念提取模型，高级设置可覆盖 |
| 修改历史 | 所有变更持久化并可撤销 |
| 时间目标 | 8–12 章节普通文档目标 3 分钟内 |
| 实施顺序 | P0 可信提取 → P1 可用图谱 → P2 智能联动 |

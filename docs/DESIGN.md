# Bobodan Design Guide

本文是 Bobodan 后续网站、Web UI 和 TUI 的长期视觉参考。目标不是追求炫技，而是让产品持续呈现温暖、自然、安静、可阅读、可陪伴的气质。

## 1. 设计定位

Bobodan 的视觉方向定义为：

> Natural Editorial Zen

也可以从产品气质上理解为：

> Warm Paper Knowledge Garden

它的核心画面是：暖米色纸张、墨蓝阅读强调、柔和植物绿、橘棕温度、少量花瓣粉、编辑部排版、自然光影和有机曲线。界面应该像一本认真排版的杂志或一本高质量笔记本，而不是后台管理系统或科技产品发布页。

纸面感采用“轻纸面质感”：暖纸色、细边框、柔和阴影、舒适排版即可，不做明显纸张纹理、胶带、贴纸或手账拟物装饰。

### 关键词

- 温暖
- 自然
- 安静
- 舒适
- 治愈
- 高级
- 克制
- 长期耐看

### 不追求

- 视觉冲击
- 炫酷动效
- 强科技感
- 纯黑纯白对比
- 大面积霓虹渐变
- 过度卡片化
- 高密度后台感

## 2. 品牌气质

Bobodan 更像一位咖啡馆主理人、设计师、作家或独立创作者，而不是企业软件、金融工具或工程师工作台。

产品应该给用户的感觉：

- 可以长时间阅读，不疲劳。
- 可以安静陪伴，不打扰。
- 信息有秩序，但不压迫。
- 功能专业，但表达温柔。
- 有品质感，但不炫耀。

## 3. 参考宇宙

Bobodan 的参考宇宙不是科技产品榜单，而是中文阅读、纸面排版、咖啡馆空间和知识花园的组合。

### 第一审美锚点

- Kami: Bobodan 的第一视觉参考。学习暖纸张、内容像放在好纸上、长文阅读、轻插图和个人知识产品气质。来源：https://github.com/tw93/Kami
- Luo 落文: Bobodan 的中文字体和长文气质参考。学习纸面排版、中文阅读、端正含蓄、有骨节的标题与正文。来源：https://github.com/tw93/Luo 和 https://luo.tw93.fun/

### 核心品牌参考

- Claude: 学橘棕温度、人文 AI、思想工具感。
- Clay: 学柔和有机形状、艺术布局、松弛的视觉节奏。
- Starbucks Reserve: 学自然绿、木质、咖啡馆空间和生活陪伴感。
- MUJI: 学东方留白、材料感、低欲望、无压迫的日常设计。
- Aesop: 学高级克制、植物气质、人文文案和安静品牌感。
- Are.na: 学知识花园、公共图书馆、虚拟笔记本和收藏结构。

### 可扩展参考

- Kinfolk: 慢生活、杂志留白、自然光摄影。
- Craft: 精致文档、块级内容、轻工作区。
- Readwise Reader: 严肃阅读、highlight、长文流。
- Bear: 简洁写作、低干扰 Markdown。
- Day One: 日记、陪伴感、个人历史。
- Moleskine: 高质量笔记本、创作者隐喻。
- Monocle: 编辑部、城市、咖啡馆、成熟生活方式。

### 产品骨架参考

这些产品可以参考功能骨架，但不能直接照抄视觉：

| 模块 | 参考 | Bobodan 吸收什么 |
|---|---|---|
| 对话区 | ChatGPT | 左侧历史 / 项目上下文、中央对话、文件入口、Canvas 思路 |
| 首页氛围 | Pi | 温和、低压、会等用户的学习伙伴感 |
| 学习卡片 | Gemini | flashcards、quizzes、study guides、互动学习材料 |
| 知识库 | Obsidian | 本地 vault、双链、概念关系、个人 Wikipedia |
| 阅读器 | Readwise Reader | 专注阅读、highlight、摘录、复习回流 |
| Agent 管理 | ClawPort / Agent Hub | Agent 状态、任务队列、记忆浏览、MCP/Cron/Logs |
| 本地助手 | OpenClaw | local-first、工具执行、设备/渠道连接、隐私感 |

吸收原则：

- 功能骨架可以参考。
- 视觉不能照抄控制台、后台、黑色终端、AI 紫渐变或 Agent dashboard。
- 所有模块最终都要回到 Kami 暖纸张、墨蓝阅读秩序、Luo 中文排版、Claude 橘棕温度和 Bobodan 的纸面学习气质。

一句话标准：

> 像给一台 Agent OS 穿上高级笔记本封皮。

## 3.1 Study / Workbench 视觉分区

Bobodan 的 Web UI 有两组空间：

```text
Study
  Today
  Chat
  Practice
  Review
  Library
  Roadmap

Workbench
  Memory
  Agents
  Skills
  MCP
  Automations
  Logs
  Settings
```

Study 是主空间：

- 视觉正常对比度。
- 更像纸面学习空间。
- 强调温暖、阅读、行动建议。
- 每个页面都应该能回到“今天学什么 / 接下来做什么”。

Workbench 是工具抽屉：

- 默认折叠。
- 低对比、小字号、弱视觉。
- 不抢 Today / Chat / Practice 的注意力。
- 可以承载 Agent OS 能力，但不能像企业 command center。

Workbench 禁止使用这些气质：

- Control Center。
- Command Center。
- Admin。
- Dashboard。
- 黑色终端风。
- 高密度运维控制台。

## 3.2 信息密度与移动端优先级

Bobodan 的默认密度是“阅读优先的中等密度”。

- Study 页面留白充足，适合阅读、对话、做题和复习。
- Workbench 可以稍微紧凑，但仍然不能变成后台表格。
- 不做极简空洞的大营销页，也不做高密度管理系统。
- 移动端优先保证 Chat、Practice、Review 三条主学习路径。
- 移动端可以弱化 Agents、MCP、Logs、Automations 等高级工具入口。

## 3.3 页面气质规则

### Today

Today 是学习伙伴首页，不是 dashboard。

结构：

```text
一句低压问候
+ 一条记忆 / 上下文
+ 2-3 个行动建议
```

推荐语气：

```text
今天想学点什么？

我记得你昨天卡在 Dijkstra 的贪心证明。
今天可以先从 3 道基础题开始，或者继续整理图算法笔记。
```

不要把 Today 设计成：

```text
知识库数量：52
MCP 连接：3
Cron：7
Logs：128
```

系统状态要翻译成学习建议。

### Chat

Chat 采用 ChatGPT 式主骨架，但视觉更像阅读器和笔记本。

必须有：

- 中央对话。
- 文件 / 资料入口。
- 学习动作入口。
- 右侧或浮层学习上下文。

回答区域要像文章，不像日志流。

### Practice

Practice 是主练习入口，使用一题一卡。

题卡应像纸面测验：

- 卡片边界轻。
- 题干层级清楚。
- 选项留白充足。
- 答案反馈温和。
- 来源和 AI 补充标签清楚。

不要做成密集刷题后台。

### Review

Review 是今日复习入口。

它应该像一份轻量学习清单：

- 到期知识点。
- 错题来源。
- 薄弱点。
- 建议练习数量。

不要做成复杂日历或大数据面板。

### Library

Library 以资料树 + 阅读/来源面板为主，局部关系为辅。

推荐结构：

```text
左侧：资料树 / vault / 课程 / 标签
中间：文档阅读视图或资料摘要
右侧：来源、双链、相关概念、小型局部图谱
```

不要把大图谱作为主舞台。概念图谱只做局部辅助。

### Reader

Reader 第一版是 Library 内阅读视图，不是独立主导航。

它应吸收 Readwise Reader 的：

- 专注阅读。
- highlight。
- 摘录。
- 稍后读。
- 复习回流。

但视觉必须保持 Bobodan 纸面阅读气质。

### Roadmap

Roadmap 只表示用户学习路线。

它应该像学习计划和课程地图：

```text
目标：两周掌握图算法
当前阶段：最短路径
今日任务：复习 Dijkstra + 做 5 道题
后续：Bellman-Ford → Floyd → 最小生成树
```

不要把 Agent 任务路线、Cron 或 Logs 混进 Roadmap。

### Canvas

Canvas 第一版是 Chat 内的临时展开面板，不是独立主功能。

推荐形态：

```text
Chat 回答
→ [整理到学习白纸]
→ 打开 Canvas 面板
→ 可编辑摘要 / 提纲 / 练习清单
```

Canvas 应像“学习白纸”，不是 Figma、Notion 或开发者 IDE。

### Memory

Memory 在主流程里自然出现，在 Workbench 中可管理。

主流程表达：

```text
我记得你更喜欢先看例子，再看定义。
上次你说图算法有点绕，我们今天从可视化例子开始。
你最近复习节奏不错，今天只安排 10 分钟。
```

Workbench 里的 Memory Browser 必须支持：

- 查看。
- 编辑。
- 删除。
- 固定。

Memory Browser 视觉要像整理索引卡，不像数据库表。

## 4. 色彩系统

### 基础色

| 用途 | Token | 色值 | 说明 |
|---|---|---|---|
| 页面背景 | `--color-paper` | `#F5F4ED` | 默认主背景，像暖米色纸张 |
| 次级背景 | `--color-paper-soft` | `#F7F5EF` | 卡片、侧栏、轻区块背景 |
| 深一点背景 | `--color-parchment` | `#F3EFE5` | 分区、阅读面板、TUI 主背景 |
| 主文字 | `--color-ink` | `#2E2B27` | 深咖啡色，替代纯黑 |
| 次级文字 | `--color-muted` | `#6F675C` | 说明文字、辅助信息 |
| 弱文字 | `--color-faint` | `#9A9185` | 时间、标签、占位文本 |

### 墨蓝色

墨蓝色是 Bobodan 的阅读主强调色，承担标题、链接、目录、当前段落、重点线条和主按钮。它比绿色更适合长文阅读，也更接近 Kami 的纸面气质。

| 用途 | Token | 色值 | 说明 |
|---|---|---|---|
| 阅读主色 | `--color-ink-blue` | `#1B365D` | 标题、链接、目录、主按钮 |
| 柔和墨蓝 | `--color-ink-blue-soft` | `#2F4F78` | hover、图标、轻强调 |
| 雾蓝底色 | `--color-ink-blue-wash` | `#E8EDF3` | 选中态、提示块、阅读高亮背景 |
| 纸上蓝灰 | `--color-ink-blue-faint` | `#A9B7C8` | 分割线、弱装饰、TUI 辅助 |

### 植物绿

| 用途 | Token | 色值 | 说明 |
|---|---|---|---|
| 自然辅助色 | `--color-sage` | `#7A9B76` | 成功、完成、植物装饰 |
| 柔和绿 | `--color-sage-soft` | `#93AA8D` | 轻状态、图标、辅助点缀 |
| 浅绿背景 | `--color-sage-mist` | `#A8C3A1` | 成功态背景 |
| 叶片浅色 | `--color-leaf-pale` | `#B8C9B1` | 少量自然装饰色 |

绿色不再作为阅读主色。它只负责自然气息和状态反馈，避免让产品变成“绿色品牌”。

### 原木色

| 用途 | Token | 色值 | 说明 |
|---|---|---|---|
| 暖木主色 | `--color-oak` | `#C89B73` | 点缀、链接 hover、插图 |
| 浅木色 | `--color-oak-soft` | `#D1A57A` | 二级强调 |
| 纸边色 | `--color-wheat` | `#CFAF88` | 分割线、边框、引用块 |

### Claude 感橘棕色

橘棕色补充 Bobodan 的温度和人文感，但不能取代墨蓝阅读主色。它只做 5-10% 的温度强调色。

| 用途 | Token | 色值 | 说明 |
|---|---|---|---|
| 橘棕强调 | `--color-clay` | `#B86F4B` | 重要提示、引用、温暖点缀 |
| 柔和橘棕 | `--color-clay-soft` | `#C98563` | hover、插图、次级 CTA |
| 浅橘棕 | `--color-clay-mist` | `#E8C9B8` | 温暖状态底色 |
| 橘棕纸底 | `--color-clay-wash` | `#F3E1D5` | 引用块、提示块、空状态背景 |

### 花瓣粉

粉色可以进入 Bobodan，但必须是低饱和、偏灰、偏纸面的花瓣粉。它表达柔和、私人、日记、情绪和完成后的轻反馈，不能变成甜品粉或少女感主色。

| 用途 | Token | 色值 | 说明 |
|---|---|---|---|
| 花瓣粉 | `--color-petal` | `#D9A7A0` | 情绪点缀、私人记录、温柔标签 |
| 柔和粉 | `--color-petal-soft` | `#E7BDB8` | hover、轻插图、次级标记 |
| 粉色纸底 | `--color-petal-wash` | `#F6E6E2` | 日记、回顾、完成反馈背景 |

粉色使用比例应低于 5%。适合个人成长、日记、复盘、收藏、喜欢、温柔提醒；不适合主按钮、导航、长文链接或大面积背景。

### 状态色

状态色也要保持低饱和，不使用刺眼红蓝。

| 状态 | Token | 色值 |
|---|---|---|
| 成功 | `--color-success` | `#7A9B76` |
| 提醒 | `--color-warning` | `#B86F4B` |
| 错误 | `--color-danger` | `#B36A5E` |
| 信息 | `--color-info` | `#1B365D` |

### Tailwind / shadcn 语义 Tokens

如果 Web UI 使用 Tailwind 或 shadcn/ui，必须把组件语义 token 映射到 Bobodan 色彩系统。禁止直接使用默认紫色、纯蓝色、纯白色或黑色主题。

```css
:root {
  --background: #F5F4ED;
  --foreground: #2E2B27;

  --card: #F7F5EF;
  --card-foreground: #2E2B27;

  --primary: #1B365D;
  --primary-foreground: #F7F5EF;

  --secondary: #E8EDF3;
  --secondary-foreground: #2E2B27;

  --muted: #F3EFE5;
  --muted-foreground: #6F675C;

  --accent: #7A9B76;
  --accent-foreground: #F7F5EF;

  --border: rgba(46, 43, 39, 0.10);
  --ring: #2F4F78;

  --destructive: #B36A5E;
}
```

语义规则：

- `primary` 只用于主行动、当前学习路径和关键链接。
- `accent` 只用于完成、自然辅助、学习进展和温和正反馈。
- `destructive` 保持低饱和，只用于删除、撤销失败、危险操作。
- `ring` 必须是墨蓝细描边，不使用强荧光蓝 focus ring。
- 默认圆角使用 `8px` 到 `14px`，不要把 shadcn 组件改成大胶囊风。

## 5. 排版

### 字体气质

排版方向是“编辑部感”，不是 SaaS 仪表盘感。标题要有阅读感，正文要长时间舒适。

建议：

- 中文标题 / 长文 / 官网 hero：优先考虑 Luo 落文。
- 中文正文：Luo 落文、霞鹜文楷、系统宋体或系统中文字体，优先纸面阅读感和稳定性。
- 英文标题：可使用有编辑感的衬线字体，如 `Georgia`、`Cormorant Garamond`、`Source Serif`。
- UI 控件：使用无衬线字体，保持清楚、克制。

### Luo 落文

Luo 适合 Bobodan 的标题、文章页、知识卡片、官网主视觉和文档页。它不适合所有小控件；按钮、菜单、输入框仍可使用系统无衬线，保持清楚。

```css
@font-face {
  font-family: "Luo";
  src: url("https://cdn.jsdelivr.net/gh/tw93/Luo@main/dist/Luo-Regular.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}

.prose,
.hero-title,
.editorial-heading {
  font-family: "Luo", "LXGW WenKai Screen", "STSong", "SimSun", serif;
}
```

字体来源标注：

> 中文字体参考 Luo 落文，作者 tw93，来源 https://github.com/tw93/Luo 与 https://luo.tw93.fun/。正式产品使用前检查仓库 README 与 LICENSE。Luo 项目说明中提到其基于 LXGW WenKai Screen 底层构建，并向 LXGW、落霞孤鹜与 Fontworks Klee One 等开源字体工作致谢。

### 字号层级

| 场景 | 建议 |
|---|---|
| 官网 H1 | 44-64px，移动端 34-42px |
| 页面标题 | 28-36px |
| 区块标题 | 22-28px |
| 正文 | 16-18px |
| UI 标签 | 13-14px |
| 辅助说明 | 12-13px |

规则：

- 字重不要太重，标题多用 `500` 或 `600`。
- 字间距保持 `0`，不要使用负字距。
- 正文行高建议 `1.7` 到 `1.9`。
- 一行文字不宜过长，阅读区域宽度控制在 `680px` 到 `760px`。

## 6. 空间与布局

Bobodan 的空间原则是：先留白，再组织信息。

### 页面节奏

- 大段内容之间保留明显呼吸空间。
- 主要内容不要贴边，桌面端推荐最大宽度 `1120px` 到 `1200px`。
- 阅读页内容宽度更窄，推荐 `720px` 左右。
- 不把每个区块都做成卡片；页面 section 应该像杂志版面一样自然展开。

### 栅格

官网和内容页：

- 使用 12 栅格或简单双栏。
- 左侧文字、右侧辅助内容可以存在，但不要做硬切割。
- 图片、引文、功能说明应像编辑排版里的内容模块，而不是堆叠卡片。

Web App：

- 顶部或左侧导航应轻量。
- 主阅读/创作区域优先。
- 工具栏不要压迫内容。
- 信息密度中低，不走后台表格路线。

TUI：

- 使用清晰分区，但边框要轻。
- 主内容宽度优先，不用过多嵌套框。
- 状态提示放在底部或右上角，不打断当前阅读流。

## 7. 形状与光影

### 圆角

- 小控件：`8px`
- 面板：`14px`
- 重要浮层：`22px`
- 有机装饰形状可以更圆，但不要滥用。

### 阴影

阴影要像自然光，而不是悬浮广告。

推荐：

```css
box-shadow: 0 4px 12px rgba(46, 43, 39, 0.04);
box-shadow: 0 8px 24px rgba(46, 43, 39, 0.07);
```

避免：

```css
box-shadow: 0 20px 60px rgba(0, 0, 0, 0.15);
```

### 边框

边框颜色建议使用：

```css
border-color: rgba(46, 43, 39, 0.10);
```

边框应该像纸张分隔线，不像管理后台的表格线。

## 8. 网站设计规则

官网应该像“产品杂志首页”，不是传统 SaaS landing page。

### 首屏

首屏必须直接传达 Bobodan 的核心身份：一个安静、自然、可陪伴的学习与知识助手。

建议：

- 背景使用暖米色。
- H1 可以是 Bobodan 或一句极短的产品定位。
- 副标题解释产品价值，不堆功能。
- 主视觉可以是自然光、纸张、笔记、绿植、桌面、阅读界面的真实组合。
- 不使用纯渐变 hero，不使用大面积科技蓝紫。

### 内容结构

推荐顺序：

1. 产品一句话定位。
2. 一个安静的主视觉。
3. 核心使用场景：阅读、整理、问答、复习、记忆。
4. 功能说明，但保持编辑排版。
5. 示例工作流。
6. 设计克制的 CTA。

### 图片

图片要有真实感和生活感。适合：

- 纸张纹理
- 木桌
- 自然光
- 笔记本
- 咖啡馆
- 绿植
- 阅读或知识卡片界面截图

避免：

- 抽象 3D 球体
- 霓虹网络线
- 机器人形象
- 过度商业图库感
- 暗黑科技背景

## 9. Web UI 设计规则

Web UI 是用户长期工作的地方，必须安静、耐看、好阅读。

### 核心组件规范

Bobodan 的 Web UI 先规范高频学习组件，不先做庞大的完整 Design System。

| 组件 | 设计规则 |
|---|---|
| Chat composer | 像纸面书写区，底部稳定，支持资料入口、学习动作和发送。不要做霓虹输入框或厚重工具栏。 |
| AI 回答块 | 采用笔记正文式回答，不使用普通聊天气泡作为主形态。工具调用、搜索、推理痕迹默认折叠。 |
| 来源 chip | 关键结论旁显示轻量来源标注，如 `本地资料`、`网页来源`、`AI 补充`、`待核实`。点击后展开来源详情。 |
| Practice 题卡 | 一题一卡，像干净练习纸。题干、选项、答案反馈和来源标注明确分层。 |
| Practice 操作区 | 底部固定提交、下一题、问 AI、退出练习等操作，位置稳定，不随内容跳动。 |
| 问 AI 抽屉 | 在当前题目内打开轻量抽屉，只围绕当前题目、知识点和资料回答。不能把做题页变成完整聊天页。 |
| Review 条目 | 以今日复习队列呈现，显示来源、掌握状态和推荐动作，不做纯错题后台。 |
| Memory 提示 | 在 Today、Chat、Review 中轻量出现，说明“基于你的偏好/近期薄弱点/长期目标”。必须可查看、编辑、删除。 |
| Workbench 抽屉 | Agents、MCP、Logs 等放在低权重工具抽屉里，默认不抢 Study 主舞台。 |
| Canvas 面板 | Chat 内的临时学习白纸，用于整理摘要、提纲、练习清单。不是独立 IDE 或 Figma。 |

### 导航

- 导航栏背景使用 `--color-paper-soft` 或透明。
- 当前项用 `--color-sage` 或浅绿底表示。
- 导航文字小而清楚，不做厚重按钮。

### 按钮

主按钮：

```css
.button-primary {
  background: #1B365D;
  color: #F7F5EF;
  border-radius: 8px;
  box-shadow: 0 4px 12px rgba(46, 43, 39, 0.04);
}
```

次按钮：

- 背景透明或浅纸色。
- 边框用低透明深咖啡。
- hover 使用雾蓝底色、浅植物绿或浅木色。

橘棕按钮：

- 只用于次级 CTA、温暖提醒或编辑推荐。
- 不长期占用主按钮地位。
- 不大面积铺满导航或页面背景。

花瓣粉按钮：

- 只用于喜欢、收藏、日记、回顾、情绪记录等私人场景。
- 不能作为产品主 CTA。
- 不和橘棕同时大面积出现，避免页面变脏。

### 卡片

卡片只用于独立内容单元，不要套娃。

卡片风格：

- 背景：`#F7F5EF`
- 边框：`rgba(46, 43, 39, 0.08)`
- 阴影：轻到几乎看不见
- 圆角：`14px`
- 内边距：`20px` 到 `28px`

### 输入框

输入框应该像笔记纸上的书写区域。

- 背景使用 `#F7F5EF` 或 `#F5F4ED`。
- focus 状态用墨蓝细描边；成功类输入可用植物绿。
- 不使用强蓝色 focus ring。
- placeholder 使用 `#9A9185`。

### 消息与回答

AI 回答区应接近阅读器：

- 宽度受控。
- 正文行高较高。
- 引用块使用浅木色或橘棕色左边线。
- 代码块使用温暖浅底，不使用纯黑。
- 重要结论用浅绿底或细线标出，不用警报式大色块。

### 状态反馈

状态反馈采用“温和学习语气 + 明确状态标签”。

推荐：

- `正在整理你的资料`
- `正在生成 5 道练习题`
- `网页来源`
- `AI 补充`
- `待核实`
- `已加入复习`

避免：

- `Loading...`
- `Done`
- `Failed`
- `SYSTEM RUNNING`

状态可以温和，但必须明确。涉及网页资料、AI 补充、搜索结果、题目生成、记忆写入时，不能只用情绪化文案代替事实标签。

## 10. TUI 设计规则

TUI 要把 Natural Editorial Zen 翻译成终端语言：低对比、暖色、清楚、有呼吸感。

### 终端配色

| 语义 | 建议颜色 |
|---|---|
| 背景 | `#F3EFE5` 或终端近似暖米色 |
| 主文字 | `#2E2B27` |
| 次级文字 | `#6F675C` |
| 强调 | `#1B365D` |
| 选中 | `#E8EDF3` 背景 + `#2E2B27` 文字 |
| 成功 | `#7A9B76` |
| 警告 | `#B86F4B` |
| 错误 | `#B36A5E` |

如果终端不支持真彩色，则使用：

- 背景：默认或 bright white 的低亮替代。
- 主文字：black / bright black。
- 强调：blue 或 bright blue 的低强度替代。
- 成功：green，但避免 bright green。
- 警告：yellow 或 red 的低强度替代，但降低使用频率。

### TUI 布局

推荐结构：

```text
 Bobodan
 ------------------------------------------------------------
 当前任务 / 当前知识库 / 当前模式

 主内容区
   用自然段组织信息
   少用密集表格
   需要列表时保持短句

 ------------------------------------------------------------
 状态：ready   模式：learn   提示：/help
```

规则：

- 边框用细线或浅色，不做厚重 ASCII 框。
- 不连续使用多层 box。
- 当前状态要清楚，但不要抢主内容。
- 命令提示要简短，像编辑器底栏，不像服务器日志。

### TUI 文案

TUI 的文案要短、温和、确定。

推荐：

- `已整理 12 条笔记`
- `正在阅读知识库`
- `需要选择一个来源`
- `没有找到匹配内容`

避免：

- `ERROR!!!`
- `FAILED TO EXECUTE`
- `SYSTEM RUNNING`
- `Processing... please wait...`

## 11. 动效

动效只用于帮助理解状态，不用于炫技。

推荐：

- 轻微 fade
- 慢速 slide
- 150ms 到 240ms 的 hover 过渡
- 阅读进度或生成状态的柔和变化

避免：

- 弹跳
- 强缩放
- 复杂粒子
- 高频闪烁
- 自动播放的大段动画

## 12. 内容语气

Bobodan 的界面文案应该像一位安静的编辑，而不是营销人员或系统管理员。

默认语气是温和、清楚、低压的学习伙伴。后续用户可以设计自己喜欢的人设，因此产品要区分“系统默认语气”和“用户自定义人设”。

### 语气原则

- 少说形容词，多说下一步。
- 不制造焦虑。
- 不使用夸张承诺。
- 不频繁感叹。
- 不用命令式压迫用户。

### 人设可配置原则

- 用户可以配置 Bobodan 的称呼、说话风格、学习陪伴方式和反馈强度。
- 人设影响表达方式，不改变事实标注、来源标注和安全边界。
- 默认人设不能过度拟人、过度撒娇或频繁感叹。
- 当用户选择强人设时，学习状态、来源、AI 补充、待核实等标签仍要保持清楚。
- 记忆系统可以沉淀用户画像、学习偏好、长期目标和互动偏好，但必须提供查看、编辑、删除入口。

### 示例

推荐：

- `继续整理`
- `加入笔记`
- `生成复习卡片`
- `今天先看到这里`
- `这段内容可以拆成 3 个概念`

避免：

- `立即提升你的学习效率 10 倍`
- `一键爆改知识库`
- `AI 全自动颠覆学习`
- `你必须先完成配置`

## 13. 组件检查清单

每次设计 Bobodan 网站、Web UI 或 TUI 前，先检查：

- 背景是否偏暖，而不是纯白。
- 阅读主色是否是墨蓝，而不是绿色。
- 绿色是否只作为自然辅助和状态反馈。
- 橘棕色是否只作为温度点缀，而不是抢主色。
- 粉色是否是低饱和花瓣粉，且只做情绪点缀。
- 文字是否使用深咖啡，而不是纯黑。
- 中文标题和长文是否有纸面阅读感。
- 页面是否有足够留白。
- 信息是否像阅读材料，而不是后台面板。
- 阴影是否轻。
- 圆角是否柔和但不过度。
- 是否避免了蓝紫渐变、霓虹、高对比科技感。
- 是否减少了不必要的卡片。
- 是否能长时间阅读。
- 是否避免了卡片套卡片。
- 是否避免了大圆角胶囊按钮。
- 来源 chip 是否清楚标注了本地资料、网页来源、AI 补充或待核实。
- Practice 是否仍是一题一卡，而不是题库后台。
- Review 是否像今日复习队列，而不是数据库列表。
- Workbench 是否保持低权重，没有压过 Study。
- 移动端是否优先保证 Chat、Practice、Review。
- 用户自定义人设是否没有覆盖事实标签和来源标注。

## 14. 反模式

以下方向默认不适合 Bobodan。后续设计和实现必须把这些当作硬约束，而不是可选建议：

- 暗黑终端黑客风
- Stripe/Vercel 式冷白科技风
- Linear/Raycast 式极客工具风
- 企业 ERP 后台风
- 金融交易高密度风
- 大面积玻璃拟态
- 大面积蓝紫渐变
- 大面积橘棕导致页面变成复古咖啡色主题
- 大面积粉色导致页面变成甜品、少女或美妆主题
- 大面积绿色导致页面变成健康、园艺或咖啡品牌主题
- 纯图标堆叠的工具面板
- 过度可爱化或玩具化
- 大圆角胶囊按钮作为主要 UI 语言
- 卡片套卡片、面板套面板
- 装饰性光球、渐变球、bokeh 背景
- 让 Agents、MCP、Logs 直接占据首页主舞台
- 把 Practice 做成高密度题库后台
- 把 Review 做成复杂数据看板
- 用人设语气掩盖来源、AI 补充或待核实状态

## 15. 一句话标准

如果一个界面看起来像：

> 暖米色纸张上的一套安静学习工具，中文排版有风骨，墨蓝负责阅读秩序，橘棕负责温度，植物绿负责自然气息，少量花瓣粉负责私人情绪，信息像杂志一样被认真排版。

它就接近 Bobodan 的方向。

如果一个界面看起来像：

> 科技公司 dashboard、AI 发布页、交易系统或运维控制台。

它就偏离了 Bobodan 的方向。

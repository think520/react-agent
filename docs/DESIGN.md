# Bobodan Design Guide

本文是 Bobodan 后续网站、Web UI 和 TUI 的长期视觉参考。目标不是追求炫技，而是让产品持续呈现温暖、自然、安静、可阅读、可陪伴的气质。

## 1. 设计定位

Bobodan 的视觉方向定义为：

> Natural Editorial Zen

它的核心画面是：暖米色纸张、柔和植物绿、原木色、编辑部排版、自然光影和有机曲线。界面应该像一本认真排版的杂志或一本高质量笔记本，而不是后台管理系统或科技产品发布页。

### 关键词

- 温暖
- 自然
- 安静
- 舒适
- 治愈
- 高级
- 克制
- 长期耐看

### 不追求

- 视觉冲击
- 炫酷动效
- 强科技感
- 纯黑纯白对比
- 大面积霓虹渐变
- 过度卡片化
- 高密度后台感

## 2. 品牌气质

Bobodan 更像一位咖啡馆主理人、设计师、作家或独立创作者，而不是企业软件、金融工具或工程师工作台。

产品应该给用户的感觉：

- 可以长时间阅读，不疲劳。
- 可以安静陪伴，不打扰。
- 信息有秩序，但不压迫。
- 功能专业，但表达温柔。
- 有品质感，但不炫耀。

## 4. 排版

### 字体气质

排版方向是“编辑部感”，不是 SaaS 仪表盘感。标题要有阅读感，正文要长时间舒适。

建议：

- 中文正文：系统默认中文字体即可，优先清晰和稳定。
- 英文标题：可使用有编辑感的衬线字体，如 `Georgia`、`Cormorant Garamond`、`Source Serif`。
- UI 控件：使用无衬线字体，保持清楚、克制。

### 字号层级

| 场景 | 建议 |
|---|---|
| 官网 H1 | 44-64px，移动端 34-42px |
| 页面标题 | 28-36px |
| 区块标题 | 22-28px |
| 正文 | 16-18px |
| UI 标签 | 13-14px |
| 辅助说明 | 12-13px |

规则：

- 字重不要太重，标题多用 `500` 或 `600`。
- 字间距保持 `0`，不要使用负字距。
- 正文行高建议 `1.7` 到 `1.9`。
- 一行文字不宜过长，阅读区域宽度控制在 `680px` 到 `760px`。

## 5. 空间与布局

Bobodan 的空间原则是：先留白，再组织信息。

### 页面节奏

- 大段内容之间保留明显呼吸空间。
- 主要内容不要贴边，桌面端推荐最大宽度 `1120px` 到 `1200px`。
- 阅读页内容宽度更窄，推荐 `720px` 左右。
- 不把每个区块都做成卡片；页面 section 应该像杂志版面一样自然展开。

### 栅格

官网和内容页：

- 使用 12 栅格或简单双栏。
- 左侧文字、右侧辅助内容可以存在，但不要做硬切割。
- 图片、引文、功能说明应像编辑排版里的内容模块，而不是堆叠卡片。

Web App：

- 顶部或左侧导航应轻量。
- 主阅读/创作区域优先。
- 工具栏不要压迫内容。
- 信息密度中低，不走后台表格路线。

TUI：

- 使用清晰分区，但边框要轻。
- 主内容宽度优先，不用过多嵌套框。
- 状态提示放在底部或右上角，不打断当前阅读流。

## 6. 形状与光影

### 圆角

- 小控件：`8px`
- 面板：`14px`
- 重要浮层：`22px`
- 有机装饰形状可以更圆，但不要滥用。

### 阴影

阴影要像自然光，而不是悬浮广告。

推荐：

```css
box-shadow: 0 4px 12px rgba(46, 43, 39, 0.04);
box-shadow: 0 8px 24px rgba(46, 43, 39, 0.07);
```

避免：

```css
box-shadow: 0 20px 60px rgba(0, 0, 0, 0.15);
```

### 边框

边框颜色建议使用：

```css
border-color: rgba(46, 43, 39, 0.10);
```

边框应该像纸张分隔线，不像管理后台的表格线。

## 7. 网站设计规则

官网应该像“产品杂志首页”，不是传统 SaaS landing page。

### 首屏

首屏必须直接传达 Bobodan 的核心身份：一个安静、自然、可陪伴的学习与知识助手。

建议：

- 背景使用暖米色。
- H1 可以是 Bobodan 或一句极短的产品定位。
- 副标题解释产品价值，不堆功能。
- 主视觉可以是自然光、纸张、笔记、绿植、桌面、阅读界面的真实组合。
- 不使用纯渐变 hero，不使用大面积科技蓝紫。

### 内容结构

推荐顺序：

1. 产品一句话定位。
2. 一个安静的主视觉。
3. 核心使用场景：阅读、整理、问答、复习、记忆。
4. 功能说明，但保持编辑排版。
5. 示例工作流。
6. 设计克制的 CTA。

### 图片

图片要有真实感和生活感。适合：

- 纸张纹理
- 木桌
- 自然光
- 笔记本
- 咖啡馆
- 绿植
- 阅读或知识卡片界面截图

避免：

- 抽象 3D 球体
- 霓虹网络线
- 机器人形象
- 过度商业图库感
- 暗黑科技背景

## 8. Web UI 设计规则

Web UI 是用户长期工作的地方，必须安静、耐看、好阅读。

### 导航

- 导航栏背景使用 `--color-paper-soft` 或透明。
- 当前项用 `--color-sage` 或浅绿底表示。
- 导航文字小而清楚，不做厚重按钮。

### 按钮

主按钮：

```css
.button-primary {
  background: #7A9B76;
  color: #F7F5EF;
  border-radius: 999px;
  box-shadow: 0 4px 12px rgba(46, 43, 39, 0.04);
}
```

次按钮：

- 背景透明或浅纸色。
- 边框用低透明深咖啡。
- hover 使用浅植物绿或浅木色。

### 卡片

卡片只用于独立内容单元，不要套娃。

卡片风格：

- 背景：`#F7F5EF`
- 边框：`rgba(46, 43, 39, 0.08)`
- 阴影：轻到几乎看不见
- 圆角：`14px`
- 内边距：`20px` 到 `28px`

### 输入框

输入框应该像笔记纸上的书写区域。

- 背景使用 `#F7F5EF` 或 `#F5F4ED`。
- focus 状态用植物绿细描边。
- 不使用强蓝色 focus ring。
- placeholder 使用 `#9A9185`。

### 消息与回答

AI 回答区应接近阅读器：

- 宽度受控。
- 正文行高较高。
- 引用块使用浅木色左边线。
- 代码块使用温暖浅底，不使用纯黑。
- 重要结论用浅绿底或细线标出，不用警报式大色块。

## 9. TUI 设计规则

TUI 要把 Natural Editorial Zen 翻译成终端语言：低对比、暖色、清楚、有呼吸感。

### 终端配色

| 语义 | 建议颜色 |
|---|---|
| 背景 | `#F3EFE5` 或终端近似暖米色 |
| 主文字 | `#2E2B27` |
| 次级文字 | `#6F675C` |
| 强调 | `#7A9B76` |
| 选中 | `#A8C3A1` 背景 + `#2E2B27` 文字 |
| 警告 | `#C89B73` |
| 错误 | `#B36A5E` |

如果终端不支持真彩色，则使用：

- 背景：默认或 bright white 的低亮替代。
- 主文字：black / bright black。
- 强调：green，但避免 bright green。
- 警告：yellow，但降低使用频率。

### TUI 布局

推荐结构：

```text
 Bobodan
 ------------------------------------------------------------
 当前任务 / 当前知识库 / 当前模式

 主内容区
   用自然段组织信息
   少用密集表格
   需要列表时保持短句

 ------------------------------------------------------------
 状态：ready   模式：learn   提示：/help
```

规则：

- 边框用细线或浅色，不做厚重 ASCII 框。
- 不连续使用多层 box。
- 当前状态要清楚，但不要抢主内容。
- 命令提示要简短，像编辑器底栏，不像服务器日志。

### TUI 文案

TUI 的文案要短、温和、确定。

推荐：

- `已整理 12 条笔记`
- `正在阅读知识库`
- `需要选择一个来源`
- `没有找到匹配内容`

避免：

- `ERROR!!!`
- `FAILED TO EXECUTE`
- `SYSTEM RUNNING`
- `Processing... please wait...`

## 10. 动效

动效只用于帮助理解状态，不用于炫技。

推荐：

- 轻微 fade
- 慢速 slide
- 150ms 到 240ms 的 hover 过渡
- 阅读进度或生成状态的柔和变化

避免：

- 弹跳
- 强缩放
- 复杂粒子
- 高频闪烁
- 自动播放的大段动画

## 11. 内容语气

Bobodan 的界面文案应该像一位安静的编辑，而不是营销人员或系统管理员。

### 语气原则

- 少说形容词，多说下一步。
- 不制造焦虑。
- 不使用夸张承诺。
- 不频繁感叹。
- 不用命令式压迫用户。

### 示例

推荐：

- `继续整理`
- `加入笔记`
- `生成复习卡片`
- `今天先看到这里`
- `这段内容可以拆成 3 个概念`

避免：

- `立即提升你的学习效率 10 倍`
- `一键爆改知识库`
- `AI 全自动颠覆学习`
- `你必须先完成配置`

## 12. 组件检查清单

每次设计 Bobodan 网站、Web UI 或 TUI 前，先检查：

- 背景是否偏暖，而不是纯白。
- 主色是否是柔和植物绿，而不是深科技绿。
- 文字是否使用深咖啡，而不是纯黑。
- 页面是否有足够留白。
- 信息是否像阅读材料，而不是后台面板。
- 阴影是否轻。
- 圆角是否柔和但不过度。
- 是否避免了蓝紫渐变、霓虹、高对比科技感。
- 是否减少了不必要的卡片。
- 是否能长时间阅读。

## 13. 反模式

以下方向默认不适合 Bobodan：

- 暗黑终端黑客风
- Stripe/Vercel 式冷白科技风
- Linear/Raycast 式极客工具风
- 企业 ERP 后台风
- 金融交易高密度风
- 大面积玻璃拟态
- 大面积蓝紫渐变
- 纯图标堆叠的工具面板
- 过度可爱化或玩具化

## 14. 一句话标准

如果一个界面看起来像：

> 暖米色纸张上的一套安静学习工具，带一点植物绿和原木色，信息像杂志一样被认真排版。

它就接近 Bobodan 的方向。

如果一个界面看起来像：

> 科技公司 dashboard、AI 发布页、交易系统或运维控制台。

它就偏离了 Bobodan 的方向。

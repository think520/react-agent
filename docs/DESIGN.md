# Bobodan Design Guide

本文是 Bobodan 后续网站、Web UI 和 TUI 的长期视觉参考。目标不是追求炫技，而是让产品持续呈现温暖、自然、安静、可阅读、可陪伴的气质。

## 1. 设计定位

Bobodan 的视觉方向定义为：

> Natural Editorial Zen

也可以从产品气质上理解为：

> Warm Paper Knowledge Garden

它的核心画面是：暖米色纸张、墨蓝阅读强调、柔和植物绿、橘棕温度、少量花瓣粉、编辑部排版、自然光影和有机曲线。界面应该像一本认真排版的杂志或一本高质量笔记本，而不是后台管理系统或科技产品发布页。

纸面感采用“轻纸面质感”：暖纸色、细边框、柔和阴影、舒适排版即可，不做明显纸张纹理、胶带、贴纸或手账拟物装饰。

### 关键词

- 温暖
- 自然
- 安静
- 舒适
- 治愈
- 高级
- 克制
- 长期耐看

### 不追求

- 视觉冲击
- 炫酷动效
- 强科技感
- 纯黑纯白对比
- 大面积霓虹渐变
- 过度卡片化
- 高密度后台感

## 2. 品牌气质

Bobodan 更像一位咖啡馆主理人、设计师、作家或独立创作者，而不是企业软件、金融工具或工程师工作台。

产品应该给用户的感觉：

- 可以长时间阅读，不疲劳。
- 可以安静陪伴，不打扰。
- 信息有秩序，但不压迫。
- 功能专业，但表达温柔。
- 有品质感，但不炫耀。

Bobodan 的参考宇宙不是科技产品榜单，而是中文阅读、纸面排版、咖啡馆空间和知识花园的组合。

一句话标准：

> 像给一台 Agent OS 穿上高级笔记本封皮。

## 3.1 Study / Workbench 视觉分区

Bobodan 的长期 Web UI 有两组空间：

```text
Study
  Today
  Chat
  Practice
  Review
  Library
  Roadmap

Workbench
  Memory
  Agents
  Skills
  MCP
  Automations
  Logs
  Settings
```

Web MVP 不一次展示全部入口。第一版一级导航只开放：

```text
Chat
Practice
Review
Library
```

- Today 复用 Chat 主学习画布，作为无活动会话或用户回访时的起始状态。
- Roadmap 在学习闭环稳定后再成为独立入口。
- Workbench 本轮不做完整页面，只保留后续扩展位置。
- 未实现功能不放空白导航项或不可用按钮。

Study 是主空间：

- 视觉正常对比度。
- 更像纸面学习空间。
- 强调温暖、阅读、行动建议。
- 每个页面都应该能回到“今天学什么 / 接下来做什么”。

Workbench 是工具抽屉：

- 默认折叠。
- 低对比、小字号、弱视觉。
- 不抢 Today / Chat / Practice 的注意力。
- 可以承载 Agent OS 能力，但不能像企业 command center。
- Web MVP 不因 Workbench 延迟 Chat / Practice / Review / Library。

Workbench 禁止使用这些气质：

- Control Center。
- Command Center。
- Admin。
- Dashboard。
- 黑色终端风。
- 高密度运维控制台。

## 3.2 信息密度与移动端优先级

Bobodan 的默认密度是“阅读优先的中等密度”。

- Study 页面留白充足，适合阅读、对话、做题和复习。
- Workbench 可以稍微紧凑，但仍然不能变成后台表格。
- 不做极简空洞的大营销页，也不做高密度管理系统。
- 移动端优先保证 Chat、Practice、Review、Library 四个 MVP 入口。
- 移动端可以弱化 Agents、MCP、Logs、Automations 等高级工具入口。

## 3.3 页面气质规则

### Today

Today 是学习伙伴首页，不是 dashboard。

Web MVP 中 Today 不是另一套独立页面框架，而是 Chat 的起始状态。用户发送第一条消息后自然进入会话流。

结构：

```text
一句低压问候
+ 一条记忆 / 上下文
+ 2-3 个行动建议
```

推荐语气：

```text
今天想学点什么？

我记得你昨天卡在 Dijkstra 的贪心证明。
今天可以先从 3 道基础题开始，或者继续整理图算法笔记。
```

不要把 Today 设计成：

```text
知识库数量：52
MCP 连接：3
Cron：7
Logs：128
```

系统状态要翻译成学习建议。

### Chat

Chat 采用 ChatGPT 式主骨架，但视觉更像阅读器和笔记本。

必须有：

- 中央对话。
- 文件 / 资料入口。
- 学习动作入口。
- 右侧或浮层学习上下文。

回答区域要像文章，不像日志流。

#### Composer 与状态层级

Composer 保持三层结构，不把所有控制塞进同一排工具栏：

1. 输入框内：附件、Slash、资料范围、回答深度、当前模型、发送 / 停止。
2. 输入框上方：检索、Wiki、练习生成、错误与完成结果等当前操作状态。
3. 全局连接条：只在后端断开、重连或恢复时出现，正常状态不常驻。

模型选择、回答深度和引用 chip 使用紧凑原生控件；流式回答期间模型不可切换，发送按钮变为停止图标。`@资料` 与 `@会话` 继续使用 textarea + 结构化 chip，不引入富文本编辑器。引用菜单从输入区展开，支持搜索、Tab、方向键、Enter 和 Esc；引用必须可恢复、可移除并可跳转原内容。

状态只说明系统正在读取、检索、组织或生成，不显示原始思维链。状态切换使用约 `160ms` 的透明度和轻微位移，不用单个闪烁绿点代表所有过程。

#### 设置中心

设置入口位于左侧资料库信息区，不占用 Study 一级导航。桌面使用 `960–1120px` 的居中大弹窗，最大高度约 `84vh`；移动端使用全屏设置页。背景保留当前学习页面并轻度压暗，不跳转到企业后台式独立控制台。

设置骨架固定为“搜索与分类导航 + 分组内容”：

- `Bobodan`：助手昵称、教学方式、回答深度、反馈强度和品牌头像预览。
- `我与学习`：用户称呼、个人简介和长期学习目标。
- `界面与阅读`：今楷 / 宋体、字号、内容宽度、纸纹、会话密度和减少动效。
- `AI 与模型`：Provider 状态、默认 Provider、模型名称和明确触发的测试连接。
- `记忆与数据`：记忆开关、当前资料库和本地数据边界。
- `Skills`：仅展示 Web 安全白名单中的名称、说明、来源、能力和启用状态。
- `状态与关于`：后端、Provider、资料索引、记忆、Skills 和版本等用户可理解状态。

开关与单项选择即时保存，失败时恢复旧值；用户资料与人设表单使用明确保存按钮。设置页不得编辑 API Key、`.env`、文件权限、联网权限或系统安全规则，也不得显示绝对 Skill 路径、Trace 或原始日志。

对话修改设置必须先显示前后值确认卡。只允许回答深度、教学方式、反馈强度和记忆开关；确认前不修改，拒绝后不留隐式副作用。

### Practice

Practice 是主练习入口，使用一题一卡。

题卡应像纸面测验：

- 卡片边界轻。
- 题干层级清楚。
- 选项留白充足。
- 答案反馈温和。
- 来源和 AI 补充标签清楚。

不要做成密集刷题后台。

### Review

Review 是今日复习入口。

它应该像一份轻量学习清单：

- 到期知识点。
- 错题来源。
- 薄弱点。
- 建议练习数量。

不要做成复杂日历或大数据面板。

### Library

Library 以资料树 + 阅读/来源面板为主，局部关系为辅。

推荐结构：

```text
左侧：资料树 / vault / 课程 / 标签
中间：文档阅读视图或资料摘要
右侧：来源、双链、相关概念、小型局部图谱
```

不要把大图谱作为主舞台。概念图谱只做局部辅助。

### Reader

Reader 第一版是 Library 内阅读视图，不是独立主导航。

它应吸收 Readwise Reader 的：

- 专注阅读。
- highlight。
- 摘录。
- 稍后读。
- 复习回流。

但视觉必须保持 Bobodan 纸面阅读气质。

### Roadmap

Roadmap 只表示用户学习路线。

它应该像学习计划和课程地图：

```text
目标：两周掌握图算法
当前阶段：最短路径
今日任务：复习 Dijkstra + 做 5 道题
后续：Bellman-Ford → Floyd → 最小生成树
```

不要把 Agent 任务路线、Cron 或 Logs 混进 Roadmap。

### Canvas

Canvas 第一版是 Chat 内的临时展开面板，不是独立主功能。

推荐形态：

```text
Chat 回答
→ [整理到学习白纸]
→ 打开 Canvas 面板
→ 可编辑摘要 / 提纲 / 练习清单
```

Canvas 应像“学习白纸”，不是 Figma、Notion 或开发者 IDE。

### Memory

Memory 在主流程里自然出现，在 Workbench 中可管理。

主流程表达：

```text
我记得你更喜欢先看例子，再看定义。
上次你说图算法有点绕，我们今天从可视化例子开始。
你最近复习节奏不错，今天只安排 10 分钟。
```

Workbench 里的 Memory Browser 必须支持：

- 查看。
- 编辑。
- 删除。
- 固定。

Memory Browser 视觉要像整理索引卡，不像数据库表。

## 4. 色彩系统

### 基础色

| 用途 | Token | 色值 | 说明 |
|---|---|---|---|
| 页面背景 | `--color-paper` | `#F5F4ED` | 默认主背景，像暖米色纸张 |
| 次级背景 | `--color-paper-soft` | `#F7F5EF` | 卡片、侧栏、轻区块背景 |
| 深一点背景 | `--color-parchment` | `#F3EFE5` | 分区、阅读面板、TUI 主背景 |
| 主文字 | `--color-ink` | `#2E2B27` | 深咖啡色，替代纯黑 |
| 次级文字 | `--color-muted` | `#6F675C` | 说明文字、辅助信息 |
| 弱文字 | `--color-faint` | `#9A9185` | 时间、标签、占位文本 |

### 墨蓝色

墨蓝色是 Bobodan 的阅读主强调色，承担标题、链接、目录、当前段落、重点线条和主按钮。它比绿色更适合长文阅读，也更接近 Kami 的纸面气质。

| 用途 | Token | 色值 | 说明 |
|---|---|---|---|
| 阅读主色 | `--color-ink-blue` | `#1B365D` | 标题、链接、目录、主按钮 |
| 柔和墨蓝 | `--color-ink-blue-soft` | `#2F4F78` | hover、图标、轻强调 |
| 雾蓝底色 | `--color-ink-blue-wash` | `#E8EDF3` | 选中态、提示块、阅读高亮背景 |
| 纸上蓝灰 | `--color-ink-blue-faint` | `#A9B7C8` | 分割线、弱装饰、TUI 辅助 |

### 植物绿

| 用途 | Token | 色值 | 说明 |
|---|---|---|---|
| 自然辅助色 | `--color-sage` | `#7A9B76` | 成功、完成、植物装饰 |
| 柔和绿 | `--color-sage-soft` | `#93AA8D` | 轻状态、图标、辅助点缀 |
| 浅绿背景 | `--color-sage-mist` | `#A8C3A1` | 成功态背景 |
| 叶片浅色 | `--color-leaf-pale` | `#B8C9B1` | 少量自然装饰色 |

绿色不再作为阅读主色。它只负责自然气息和状态反馈，避免让产品变成“绿色品牌”。

### 原木色

| 用途 | Token | 色值 | 说明 |
|---|---|---|---|
| 暖木主色 | `--color-oak` | `#C89B73` | 点缀、链接 hover、插图 |
| 浅木色 | `--color-oak-soft` | `#D1A57A` | 二级强调 |
| 纸边色 | `--color-wheat` | `#CFAF88` | 分割线、边框、引用块 |

### Claude 感橘棕色

橘棕色补充 Bobodan 的温度和人文感，但不能取代墨蓝阅读主色。它只做 5-10% 的温度强调色。

| 用途 | Token | 色值 | 说明 |
|---|---|---|---|
| 橘棕强调 | `--color-clay` | `#B86F4B` | 重要提示、引用、温暖点缀 |
| 柔和橘棕 | `--color-clay-soft` | `#C98563` | hover、插图、次级 CTA |
| 浅橘棕 | `--color-clay-mist` | `#E8C9B8` | 温暖状态底色 |
| 橘棕纸底 | `--color-clay-wash` | `#F3E1D5` | 引用块、提示块、空状态背景 |

### 花瓣粉

粉色可以进入 Bobodan，但必须是低饱和、偏灰、偏纸面的花瓣粉。它表达柔和、私人、日记、情绪和完成后的轻反馈，不能变成甜品粉或少女感主色。

| 用途 | Token | 色值 | 说明 |
|---|---|---|---|
| 花瓣粉 | `--color-petal` | `#D9A7A0` | 情绪点缀、私人记录、温柔标签 |
| 柔和粉 | `--color-petal-soft` | `#E7BDB8` | hover、轻插图、次级标记 |
| 粉色纸底 | `--color-petal-wash` | `#F6E6E2` | 日记、回顾、完成反馈背景 |

粉色使用比例应低于 5%。适合个人成长、日记、复盘、收藏、喜欢、温柔提醒；不适合主按钮、导航、长文链接或大面积背景。

### 状态色

状态色也要保持低饱和，不使用刺眼红蓝。

| 状态 | Token | 色值 |
|---|---|---|
| 成功 | `--color-success` | `#7A9B76` |
| 提醒 | `--color-warning` | `#B86F4B` |
| 错误 | `--color-danger` | `#B36A5E` |
| 实心危险操作 | `--color-danger-strong` | `#934D43` |
| 信息 | `--color-info` | `#1B365D` |

## 5. 排版

### 字体气质

排版方向是“编辑部感”，不是 SaaS 仪表盘感。标题要有阅读感，正文要长时间舒适。

建议：

- 品牌名与少量固定展示标题使用 Luo，形成稳定的 Bobodan 识别。
- 导航、按钮、输入框、标签、会话列表和设置项使用系统中文黑体栈，保证完整字形、清晰字重和高频操作效率。
- AI 回答、资料正文、Wiki 和阅读器使用 Noto Serif SC，形成安静的长文阅读区。
- 模型名、路径、代码和技术标识使用等宽字体。
- 不依赖浏览器合成 Luo 粗体；需要粗体的 UI 必须使用系统黑体，正文粗体由 Noto Serif SC 承担。

### 字体 Token

```css
--font-brand: "Luo", "Noto Serif SC", serif;
--font-ui: system-ui, -apple-system, "Segoe UI", "PingFang SC",
  "Microsoft YaHei UI", "Microsoft YaHei", sans-serif;
--font-reading: "Noto Serif SC", "Source Han Serif SC",
  "Songti SC", "STSong", "SimSun", serif;
--font-article: "TsangerJinKai02", "Noto Serif SC",
  "Source Han Serif SC", "Songti SC", serif;
--font-mono: ui-monospace, "Cascadia Code", monospace;
```

Bobodan 是 local-first 产品，正式 Web App 必须把字体文件随前端静态资源本地打包。不要在运行时依赖 jsDelivr、Google Fonts 或其他公共 CDN。字体加载失败时必须自然回退到本地系统字体。

Noto Serif SC 使用 Unicode Range 分片随项目分发，覆盖正文常见字、罕见字、英文、数字和 300-700 字重。前端资源保留 SIL Open Font License；Luo 继续保留其原始许可说明。

资料阅读器和 Wiki 正文使用 Kami 同款的仓耳今楷 W04/W05 完整字重。当前 Luo Web 字体约 327 KB，适合品牌与展示标题，但不是完整中文文章字库；禁止把它单独设置为长文唯一字体。文章字体必须本地加载、保留 Noto Serif SC 回退，并关闭字体合成。

> 资料文章字体参考 Kami 的仓耳今楷实现。公开分发桌面安装包前需再次核对字体作者的分发条款并保留所需署名。

### 字号层级

| 场景 | 建议 |
|---|---|
| 官网 H1 | 44-64px，移动端 34-42px |
| 页面标题 | 28-36px |
| 区块标题 | 22-28px |
| 正文 | 16-18px |
| UI 标签 | 13-14px |
| 辅助说明 | 12-13px |

规则：

- 字重不要太重，标题多用 `500` 或 `600`。
- 字间距保持 `0`，不要使用负字距。
- 正文行高建议 `1.7` 到 `1.9`。
- 一行文字不宜过长，阅读区域宽度控制在 `680px` 到 `760px`。

## 6. 空间与布局

Bobodan 的空间原则是：先留白，再组织信息。

### 页面节奏

- 大段内容之间保留明显呼吸空间。
- 主要内容不要贴边，桌面端推荐最大宽度 `1120px` 到 `1200px`。
- 阅读页内容宽度更窄，推荐 `720px` 左右。
- 不把每个区块都做成卡片；页面 section 应该像杂志版面一样自然展开。

### 栅格

官网和内容页：

- 使用 12 栅格或简单双栏。
- 左侧文字、右侧辅助内容可以存在，但不要做硬切割。
- 图片、引文、功能说明应像编辑排版里的内容模块，而不是堆叠卡片。

Web App：

- 顶部或左侧导航应轻量。
- 主阅读/创作区域优先。
- 工具栏不要压迫内容。
- 信息密度中低，不走后台表格路线。

### Web App 响应式尺寸

桌面宽屏 `>= 1280px`：

- 左侧导航宽 `240px` 到 `264px`，不随内容变化。
- 主学习区 `minmax(0, 1fr)`，正文阅读宽度 `680px` 到 `760px`。
- 学习上下文栏宽 `300px` 到 `336px`，只有存在真实上下文时显示。
- 三栏之间使用细分隔线或页面留白，不把每栏做成浮动卡片。

平板与窄桌面 `768px - 1279px`：

- 左侧导航收窄为图标栏或抽屉。
- 右侧学习上下文改为可关闭抽屉，不挤压正文。
- Chat composer、Practice 操作区和主阅读宽度保持稳定。

移动端 `< 768px`：

- 一级导航只保留 Chat、Practice、Review、Library，使用底部导航或单层菜单。
- 不显示常驻右侧栏；来源、记忆和知识点从底部 sheet / 抽屉打开。
- Chat composer 固定在安全区域上方，输入增长不能遮住最后一条回答。
- Practice 提交 / 下一题操作区固定，但必须为题目正文预留底部空间。
- 所有固定栏考虑 `env(safe-area-inset-bottom)`。

稳定尺寸规则：

- 图标按钮默认 `36px` 或 `40px` 方形，文字按钮最小高度 `40px`。
- 来源 chip、状态标签和进度数字不能改变题卡或工具栏高度。
- 不使用 viewport width 缩放字体；按断点调整布局，不按屏幕宽度连续缩放字号。

TUI：

- 使用清晰分区，但边框要轻。
- 主内容宽度优先，不用过多嵌套框。
- 状态提示放在底部或右上角，不打断当前阅读流。

## 7. 形状与光影

### 圆角

- 小控件：`6px`
- 按钮、输入框、卡片：`8px`
- 抽屉、弹窗、浮层：`12px`
- 圆形头像、状态点和纯图标圆按钮可以使用 `50%`。
- 有机曲线只用于插图、图片裁切或少量品牌装饰，不用于主要 UI 容器。

### 阴影

阴影要像自然光，而不是悬浮广告。

推荐：

```css
box-shadow: 0 4px 12px rgba(46, 43, 39, 0.04);
box-shadow: 0 8px 24px rgba(46, 43, 39, 0.07);
```

避免：

```css
box-shadow: 0 20px 60px rgba(0, 0, 0, 0.15);
```

### 边框

边框颜色建议使用：

```css
border-color: rgba(46, 43, 39, 0.10);
```

边框应该像纸张分隔线，不像管理后台的表格线。

## 8. 网站设计规则

官网应该像“产品杂志首页”，不是传统 SaaS landing page。

### 首屏

首屏必须直接传达 Bobodan 的核心身份：一个安静、自然、可陪伴的学习与知识助手。

建议：

- 背景使用暖米色。
- H1 可以是 Bobodan 或一句极短的产品定位。
- 副标题解释产品价值，不堆功能。
- 主视觉可以是自然光、纸张、笔记、绿植、桌面、阅读界面的真实组合。
- 不使用纯渐变 hero，不使用大面积科技蓝紫。

### 内容结构

推荐顺序：

1. 产品一句话定位。
2. 一个安静的主视觉。
3. 核心使用场景：阅读、整理、问答、复习、记忆。
4. 功能说明，但保持编辑排版。
5. 示例工作流。
6. 设计克制的 CTA。

### 图片

图片要有真实感和生活感。适合：

- 纸张纹理
- 木桌
- 自然光
- 笔记本
- 咖啡馆
- 绿植
- 阅读或知识卡片界面截图

避免：

- 抽象 3D 球体
- 霓虹网络线
- 机器人形象
- 过度商业图库感
- 暗黑科技背景

## 9. Web UI 设计规则

Web UI 是用户长期工作的地方，必须安静、耐看、好阅读。

### 核心组件规范

Bobodan 的 Web UI 先规范高频学习组件，不先做庞大的完整 Design System。

| 组件 | 设计规则 |
|---|---|
| Chat composer | 像纸面书写区，底部稳定，支持资料入口、学习动作和发送。不要做霓虹输入框或厚重工具栏。 |
| AI 回答块 | 采用笔记正文式回答，不使用普通聊天气泡作为主形态。工具调用、搜索、推理痕迹默认折叠。 |
| 来源 chip | 关键结论旁显示轻量归因标注：`本地资料`、`本地扩展`、`网页来源`、`AI 补充`、`待核实`。点击后展开来源详情。 |
| 资料导入区 | 接受支持格式、显示同步进度和可恢复错误。空状态的主动作是“导入资料”，不是知识库统计面板。 |
| Wiki 维护区 | 在 Wiki 分类内提供健康检查、问题详情和“整理并重建索引”。重复页只归档 Bobodan 生成内容，不删除用户原始资料。 |
| Slash 命令面板 | 输入 `/` 后贴近 composer 展示 Web 安全命令与当前可执行 Skills；支持筛选、方向键、Enter / Tab 和 Esc，不暴露 CLI 管理命令。 |
| Practice 题卡 | 一题一卡，像干净练习纸。题干、选项、答案反馈和来源标注明确分层。 |
| 练习就绪卡 | Chat 生成题目后只显示主题、题数、来源和“开始练习”；不在正文展开整套题目，重复点击不得创建重复练习。 |
| Practice 操作区 | 底部固定提交、下一题、问 AI、退出练习等操作，位置稳定，不随内容跳动。 |
| 问 AI 抽屉 | 在当前题目内打开轻量抽屉，只围绕当前题目、知识点和资料回答。不能把做题页变成完整聊天页。 |
| Review 条目 | 以今日复习队列呈现，显示来源、掌握状态和推荐动作，不做纯错题后台。 |
| Memory 提示 | 在 Today、Chat、Review 中轻量出现，说明“基于你的偏好/近期薄弱点/长期目标”。必须可查看、编辑、删除。 |
| Workbench 抽屉 | Agents、MCP、Logs 等放在低权重工具抽屉里，默认不抢 Study 主舞台。 |
| Canvas 面板 | Chat 内的临时学习白纸，用于整理摘要、提纲、练习清单。不是独立 IDE 或 Figma。 |

### 首次引导与学习范围

- 首次引导只在真正空白的工作区出现，使用四个短步骤收集称呼与目标、AI 连接、首批资料、记忆与联网边界。
- 已有会话或资料的工作区不得强制重复引导；完成状态和非敏感学习偏好可保存在浏览器本地。
- 当前学习范围必须在 Library、Chat composer 和右侧学习书桌中使用同一份状态，并由后端真正约束检索与出题。
- 资料正文允许选中文字后显示轻量“带到对话”工具条；工具条保持在正文流附近，不遮挡原文，不常驻悬浮。
- Practice 的“问 AI”使用当前题目内的轻量抽屉。桌面从右侧进入，移动端从底部进入；关闭后答案和练习进度不得丢失。
- AI 处理过程只显示状态、资料、工具与耗时摘要，默认折叠，不展示原始思维链。
- 运行中的处理状态放在 assistant 正文流内，使用 `thinking / reading / writing / ready` 对应的 Bobodan 图片；不在 composer 上方重复显示第二套状态。
- Slash 面板只显示当前 Web runtime 能完整执行的命令与 Skills；需要联网、任意写回、MCP 或桌面进程控制的能力不得伪装成可用项。

### 来源与可信度标注

| 标签 | 视觉建议 | 必须展示 |
|---|---|---|
| `本地资料` | 雾蓝底、墨蓝文字、文档图标 | 文件标题与 heading / page / slide 定位 |
| `本地扩展` | 浅纸底、墨蓝虚线边框 | 基于哪些本地资料扩展 |
| `网页来源` | 纸色底、墨蓝边框、链接图标 | 网页标题、域名、访问时间 |
| `AI 补充` | 橘棕纸底、橘棕文字 | 明确说明不是资料原文或网页引用 |
| `待核实` | 透明底、危险色边框和文字 | 缺少什么证据，以及用户可执行的核实动作 |

规则：

- 不能只用颜色区分来源；标签文字始终可见。
- chip 只展示来源类型，点击或聚焦后再显示完整来源详情。
- 本地绝对路径不直接显示给普通用户，展示可读文件名和定位即可。
- `AI 补充` 与 `待核实` 不使用文档或链接图标，避免伪装成引用。
- 同一结论有多个来源时显示前 1-2 个 chip，其余合并为 `+N`，避免正文被标签淹没。
- 本地证据不足时使用正文流内的联网确认卡，不使用全屏警告或自动弹窗；卡片必须同时提供“只用本地资料”和“联网查找”。
- 设置为“模型自动”时，模型可自行触发受限网页研究并自动采用最多 3 个高质量、域名去重来源；界面仍展示采用来源、访问时间和读取方式。
- 设置为“每次询问”时保持确认卡和候选选择；默认值为“每次询问”，不得因模型判断绕过用户偏好。
- 联网候选采用无嵌套卡片的分隔列表，默认不勾选；每项展示标题、域名、两行内摘要和来源类型建议，外链按钮与选择框保持独立。
- 读取状态按“搜索候选 → 读取 N 个来源 → 证据准备完成 / 部分失败”展示，并沿用约 `160ms` 的淡入与轻微位移。
- 网页证据行显示域名、访问时间和“直接读取 / Jina Reader 后备”；Jina 不能只藏在 tooltip 中。
- Composer 的地球图标是一次性联网开关，只影响下一条消息；开启后显示“本轮联网”范围提示，发送后自动关闭。

### 导航

- 导航栏背景使用 `--color-paper-soft` 或透明。
- 当前项使用 `--color-ink-blue-wash` 底色、墨蓝文字和清楚的图标 / 边线，不使用 sage 作为主选中态。
- sage 只用于已完成、已掌握、同步成功等正反馈状态。
- 导航文字小而清楚，不做厚重按钮。

### 按钮

主按钮：

```css
.button-primary {
  background: #1B365D;
  color: #F7F5EF;
  border-radius: 8px;
  box-shadow: 0 4px 12px rgba(46, 43, 39, 0.04);
}
```

次按钮：

- 背景透明或浅纸色。
- 边框用低透明深咖啡。
- hover 使用雾蓝底色、浅植物绿或浅木色。

橘棕按钮：

- 只用于次级 CTA、温暖提醒或编辑推荐。
- 不长期占用主按钮地位。
- 不大面积铺满导航或页面背景。

花瓣粉按钮：

- 只用于喜欢、收藏、日记、回顾、情绪记录等私人场景。
- 不能作为产品主 CTA。
- 不和橘棕同时大面积出现，避免页面变脏。

### 卡片

卡片只用于独立内容单元，不要套娃。

卡片风格：

- 背景：`#F7F5EF`
- 边框：`rgba(46, 43, 39, 0.08)`
- 阴影：轻到几乎看不见
- 圆角：`8px`
- 内边距：`20px` 到 `28px`

### 输入框

输入框应该像笔记纸上的书写区域。

- 背景使用 `#F7F5EF` 或 `#F5F4ED`。
- focus 状态用墨蓝细描边；成功类输入可用植物绿。
- 不使用强蓝色 focus ring。
- placeholder 使用 `#9A9185`。

### 消息与回答

AI 回答区应接近阅读器：

- 宽度受控。
- 正文行高较高。
- 引用块使用浅木色或橘棕色左边线。
- 代码块使用温暖浅底，不使用纯黑。
- 重要结论用浅绿底或细线标出，不用警报式大色块。

### 状态反馈

状态反馈采用“温和学习语气 + 明确状态标签”。

推荐：

- `正在整理你的资料`
- `正在生成 5 道练习题`
- `网页来源`
- `AI 补充`
- `待核实`
- `已加入复习`

避免：

- `Loading...`
- `Done`
- `Failed`
- `SYSTEM RUNNING`

状态可以温和，但必须明确。涉及网页资料、AI 补充、搜索结果、题目生成、记忆写入时，不能只用情绪化文案代替事实标签。

- Bobodan 状态图片固定约 `48–56px`，切换只使用约 `160ms` 的 opacity 与不超过 `2px` 位移；运行中允许一条细横线在固定宽度内往返伸缩，除此之外不使用持续漂浮、弹跳或循环进度动画。
- 任务完成后图片状态与横线退出，历史过程折叠为文字摘要；`prefers-reduced-motion` 下取消位移并把横线改为静态。
- `到期`、`错题`、`薄弱点` 等 2-4 字固定状态词可使用 Luo 作为纸面强调；正文、按钮和动态长文本仍使用 UI / Reading 字体。
- 可滚动工作区保留可发现性，但滚动条应使用透明轨道与暖灰细滑块；横向滚动只允许代码、表格等确有必要的内容，普通面板文本必须收缩或省略。

### 关键页面状态

| 页面 | Empty | Loading / Running | Error | Completed |
|---|---|---|---|---|
| Chat | 一句低压问候 + composer + 2-3 个真实动作 | 流式正文 + 单行温和状态，不显示日志瀑布 | 保留用户输入，提供重新发送；后端不可用时说明恢复动作 | 回答、来源和后续学习动作稳定落位 |
| Practice | 选择资料 / 主题 / 薄弱点创建练习 | Bobodan writing 状态保持表单尺寸稳定 | 保留主题和资料范围；本地不足时给出联网确认，不作为系统错误 | 显示正确率、错题、掌握度变化和推荐复习 |
| Review | `今天没有到期复习`，提供回到 Chat / Practice 的动作 | 队列骨架不闪烁、不重排 | 区分数据为空与读取失败 | 完成项弱化但可撤销，不用庆典动画 |
| Library | 主动作是导入资料，显示支持格式 | 显示文件级同步进度 | 文件级错误可展开、重试或移除 | 显示资料标题、状态和最近同步时间 |

规则：

- Empty、Loading、Error 不能共用同一句模糊文案。
- skeleton 必须匹配最终组件尺寸，不能加载完成后大幅跳动。
- 操作失败时保留用户输入和已完成进度，不用整页错误覆盖。
- 成功反馈轻量、可撤销，不使用彩带、弹跳或大面积绿色。

### 可访问性与主题策略

- 正常文本对比度至少 `4.5:1`；大字、图标和控件边界至少 `3:1`。
- 所有交互元素必须有可见 focus，不能只依赖 hover。
- Chat composer、来源详情、Practice 选项、抽屉和弹窗必须支持完整键盘操作。
- 移动端主要触控目标至少 `44px × 44px`；紧凑桌面图标按钮不得小于 `36px × 36px`。
- 状态不能只靠颜色表达；必须同时使用文字、图标、边框或形状。
- 流式回答使用节制的 `aria-live` 状态，不让屏幕阅读器逐 token 重复朗读。
- 尊重 `prefers-reduced-motion`，关闭非必要 fade / slide，并停止自动滚动动画。
- 第一版只做暖纸浅色主题，不自动跟随系统切换暗色，也不通过滤镜反转生成暗色模式。
- 后续若做暗色主题，必须单独定义可读的“夜间纸面”token，不复用黑色终端主题。

## 10. TUI 设计规则

TUI 要把 Natural Editorial Zen 翻译成终端语言：低对比、暖色、清楚、有呼吸感。

### 终端配色

| 语义 | 建议颜色 |
|---|---|
| 背景 | `#F3EFE5` 或终端近似暖米色 |
| 主文字 | `#2E2B27` |
| 次级文字 | `#6F675C` |
| 强调 | `#1B365D` |
| 选中 | `#E8EDF3` 背景 + `#2E2B27` 文字 |
| 成功 | `#7A9B76` |
| 警告 | `#B86F4B` |
| 错误 | `#B36A5E` |

如果终端不支持真彩色，则使用：

- 背景：默认或 bright white 的低亮替代。
- 主文字：black / bright black。
- 强调：blue 或 bright blue 的低强度替代。
- 成功：green，但避免 bright green。
- 警告：yellow 或 red 的低强度替代，但降低使用频率。

### TUI 布局

推荐结构：

```text
 Bobodan
 ------------------------------------------------------------
 当前任务 / 当前知识库 / 当前模式

 主内容区
   用自然段组织信息
   少用密集表格
   需要列表时保持短句

 ------------------------------------------------------------
 状态：ready   模式：learn   提示：/help
```

规则：

- 边框用细线或浅色，不做厚重 ASCII 框。
- 不连续使用多层 box。
- 当前状态要清楚，但不要抢主内容。
- 命令提示要简短，像编辑器底栏，不像服务器日志。

### TUI 文案

TUI 的文案要短、温和、确定。

推荐：

- `已整理 12 条笔记`
- `正在阅读知识库`
- `需要选择一个来源`
- `没有找到匹配内容`

避免：

- `ERROR!!!`
- `FAILED TO EXECUTE`
- `SYSTEM RUNNING`
- `Processing... please wait...`

## 11. 动效

动效只用于帮助理解状态，不用于炫技。

推荐：

- 轻微 fade
- 仅在弹窗、抽屉和状态解释需要空间关系时使用短距离 slide
- 按钮按压 `100–160ms`，Popover `140–180ms`，状态变化约 `160ms`，弹窗约 `220ms`
- 阅读进度或生成状态的柔和变化
- 进入使用有即时反馈的 ease-out，持续移动使用 ease-in-out；不使用起步迟缓的 ease-in
- 只过渡 `opacity` 和 `transform` 等低成本属性，高频键盘菜单不添加明显开关动画

避免：

- 弹跳
- 强缩放
- 复杂粒子
- 高频闪烁
- 自动播放的大段动画
- `transition: all`
- 从 `scale(0)` 出现的控件

`prefers-reduced-motion` 或用户选择“减少动态效果”时，取消位移、循环和自动滚动动画，只保留短淡入与必要的颜色反馈。

## 12. 内容语气

Bobodan 的界面文案应该像一位安静的编辑，而不是营销人员或系统管理员。

默认语气是温和、清楚、低压的学习伙伴。后续用户可以设计自己喜欢的人设，因此产品要区分“系统默认语气”和“用户自定义人设”。

### 语气原则

- 少说形容词，多说下一步。
- 不制造焦虑。
- 不使用夸张承诺。
- 不频繁感叹。
- 不用命令式压迫用户。

### 人设可配置原则

- 用户可以配置 Bobodan 的称呼、说话风格、学习陪伴方式和反馈强度。
- 人设影响表达方式，不改变事实标注、来源标注和安全边界。
- 默认人设不能过度拟人、过度撒娇或频繁感叹。
- 当用户选择强人设时，学习状态、来源、AI 补充、待核实等标签仍要保持清楚。
- 记忆系统可以沉淀用户画像、学习偏好、长期目标和互动偏好，但必须提供查看、编辑、删除入口。

### 示例

推荐：

- `继续整理`
- `加入笔记`
- `生成复习卡片`
- `今天先看到这里`
- `这段内容可以拆成 3 个概念`

避免：

- `立即提升你的学习效率 10 倍`
- `一键爆改知识库`
- `AI 全自动颠覆学习`
- `你必须先完成配置`

## 13. 组件检查清单

每次设计 Bobodan 网站、Web UI 或 TUI 前，先检查：

- 背景是否偏暖，而不是纯白。
- 阅读主色是否是墨蓝，而不是绿色。
- 绿色是否只作为自然辅助和状态反馈。
- 橘棕色是否只作为温度点缀，而不是抢主色。
- 粉色是否是低饱和花瓣粉，且只做情绪点缀。
- 文字是否使用深咖啡，而不是纯黑。
- 中文标题和长文是否有纸面阅读感。
- 页面是否有足够留白。
- 信息是否像阅读材料，而不是后台面板。
- 阴影是否轻。
- 圆角是否柔和但不过度。
- 是否避免了蓝紫渐变、霓虹、高对比科技感。
- 是否减少了不必要的卡片。
- 是否能长时间阅读。
- 是否避免了卡片套卡片。
- 是否避免了大圆角胶囊按钮。
- 来源 chip 是否清楚标注了本地资料、本地扩展、网页来源、AI 补充或待核实。
- 来源状态是否同时使用文字和视觉线索，而不是只靠颜色。
- 当前导航是否使用墨蓝体系，而不是把 sage 当作主选中态。
- Practice 是否仍是一题一卡，而不是题库后台。
- Review 是否像今日复习队列，而不是数据库列表。
- Workbench 是否保持低权重，没有压过 Study。
- MVP 是否只开放 Chat、Practice、Review、Library，Today 是否复用了 Chat 画布。
- 移动端是否优先保证 Chat、Practice、Review、Library。
- Empty / Loading / Error / Completed 状态是否明确且不造成布局跳动。
- 字体、图标和核心静态资源是否可以离线加载。
- 正文对比度、focus、键盘操作和减少动效是否通过检查。
- 用户自定义人设是否没有覆盖事实标签和来源标注。

## 14. 反模式

以下方向默认不适合 Bobodan。后续设计和实现必须把这些当作硬约束，而不是可选建议：

- 暗黑终端黑客风
- Stripe/Vercel 式冷白科技风
- Linear/Raycast 式极客工具风
- 企业 ERP 后台风
- 金融交易高密度风
- 大面积玻璃拟态
- 大面积蓝紫渐变
- 大面积橘棕导致页面变成复古咖啡色主题
- 大面积粉色导致页面变成甜品、少女或美妆主题
- 大面积绿色导致页面变成健康、园艺或咖啡品牌主题
- 纯图标堆叠的工具面板
- 过度可爱化或玩具化
- 大圆角胶囊按钮作为主要 UI 语言
- 卡片套卡片、面板套面板
- 装饰性光球、渐变球、bokeh 背景
- 运行时依赖公共字体 CDN，导致离线界面退化
- 用颜色作为来源、正确性或状态的唯一表达
- 用滤镜反转或纯黑背景快速拼出暗色模式
- 让 Agents、MCP、Logs 直接占据首页主舞台
- 把 Practice 做成高密度题库后台
- 把 Review 做成复杂数据看板
- 用人设语气掩盖来源、AI 补充或待核实状态

## 15. 一句话标准

如果一个界面看起来像：

> 暖米色纸张上的一套安静学习工具，中文排版有风骨，墨蓝负责阅读秩序，橘棕负责温度，植物绿负责自然气息，少量花瓣粉负责私人情绪，信息像杂志一样被认真排版。

它就接近 Bobodan 的方向。

如果一个界面看起来像：

> 科技公司 dashboard、AI 发布页、交易系统或运维控制台。

它就偏离了 Bobodan 的方向。
